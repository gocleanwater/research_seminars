# 논문 슬라이드 제작 규칙

## 범위와 근거

- 이 폴더는 논문별 HTML 슬라이드 프로젝트다. 공부 기록은 중앙 연구 위키에 보존한다.
- 논문의 원문·사용자의 공부 기록·현재 채팅에서 실제 확인한 내용을 바탕으로 한국어로 작성한다.
- 저자 주장, 실험 결과, 설명을 위한 해석, 미확인 사항을 구분한다. 없는 실험·근거·이해를 만들어내지 않는다.
- 출처는 슬라이드에서 읽을 수 있게 Section/Figure/Table/Equation과 PDF 쪽수를 표시한다.
- 공부 중인 내용과 미해결 질문을 발표 분량을 이유로 임의 생략하지 않는다. 장수와 발표 시간을 먼저 제한하지 않는다.

## 전체 초안 제작 후 한 장씩 검토 — 2026-11-05 사용자 변경

1. `PROJECT.md`, `OUTLINE.md`, `review/PROGRESS.md`, `review/FEEDBACK.md`를 먼저 읽는다.
2. 처음에는 공부 범위와 전체 목차를 제안한다. 사용자 확인 전 전체 내용을 한 번에 만들지 않는다.
3. 최신 사용자 지시: "그냥 한장한장씩 하지 말고 전체 맥락을 가지고 전체 발표 html을 다 만들어봐! 그리고 한장씩한장씩 수정해보자!" 승인된 전체 목차를 바탕으로 전체 HTML 초안을 먼저 제작한다. 이후 한 장씩 수정·검토한다. 초기 제작에 개별 장 승인을 선행 조건으로 두지 않는다.
   - 최신 지시 "화살표 때문에 늘어나는 페이지 수는 괜찮으니까 그냥 페이지 수 상관 쓰지 마"에 따라 이전30장 한도를 해제한다. 설명의 단계와 흐름을 우선하고 상세 공부 내용은 N 해설에 보존한다.
   - 장 ID와 실제 발표 순서를 분리한다. 기존 S001·P ID 및 상세 S002–S122의 의미를 유지하고, 새 설명에는 새 ID를 부여한다. 통합으로 퇴역한 P003·P004는 다른 의미로 재사용하지 않는다.
   - 표지는 Fig.1을 사용한다. 섹션명은 Problems → RLDX-1 Architecture → Training Data → Training Procedure → Inference Strategy → Evaluation and Analysis → Ablation and Analysis → Conclusion → My opinions and limitation이다. Architecture는 Fig.2 overview 뒤에 Fig.3 구조를 설명한다.
   - Fig.3의 Vision Encoder·VLM에만 클릭/방향키 기반 확대·축소·단계별 화살표를 구현한다. 수식 설명은 별도 장에 둔다. 상단 우측 근거 분류 표지는 제거하고 좌측 섹션·짧은 명사형 제목을 사용한다.
4. 실제 HTML을 실행해 PNG 미리보기를 만들고 직접 확인한다. 생성형 이미지로 슬라이드 화면을 대체하지 않는다.
5. 미리보기 이미지와 핵심 의도·근거·검토할 부분을 간결하게 보여준다. 로컬 이미지는 절대 경로로 표시한다.
6. 전체 초안 완성 후 사용자의 피드백을 기록하고 해당 장을 수정한다. 전체 제작 허가를 개별 장 승인으로 간주하지 않는다.
7. 승인은 슬라이드 ID와 버전에 연결해 `review/PROGRESS.md`에 기록한다. 요청에만 근거해 승인 여부를 추정하지 않는다.
8. 승인된 장의 내용이나 디자인을 바꾸면 재검토 필요로 표시한다. 공통 CSS 변경도 영향을 받은 승인 장을 다시 확인한다.

## 재개와 품질

- 세션을 마칠 때 현재 장·버전·피드백·다음 할 일을 기록한다. 다른 채팅에서도 파일로 이어갈 수 있게 한다.
- 각 장은 안정적인 ID를 사용하고, 화면 순서 번호와 구분한다. 번호가 바뀌어도 피드백 대상을 잃지 않는다.
- 직접 편집 원본은 `sections/01-problems.md`부터 `sections/09-my-opinions-and-limitation.md`까지 아홉 Markdown 파일이다. 본문·상세 공부 기록·Figure 3 단계 문구를 해당 MD에서 수정한다. 구조와 필드 규칙은 `sections/README.md`를 따른다.
- `scripts/migrate_sections.py`는 기존 JSON에서 MD를 처음 만든 일회성 마이그레이터다. 평소 편집·빌드에서 다시 실행하지 않는다. 특히 `--force`로 이후 MD 편집을 덮어쓰지 않는다.
- `scripts/build_deck.py`는 아홉 MD를 읽어 `slides.md`와 `presentation.html`을 생성하는 진입점이다. `content/main-*.json`과 기존 상세 JSON은 마이그레이션 시점의 스냅샷으로 보존하며 현재 편집 원본으로 쓰지 않는다. 생성 HTML·slides.md만 수정해 원본과 불일치시키지 않는다.
- Figure 3의 문구는 Architecture MD에서, 카메라·화살표 좌표 등 위치 설정은 `content/architecture-tour.json`에서 관리한다. 수식은 확대 그림에 억지로 합치지 않고 별도 설명 장을 유지한다.
- 상세한 공부 내용을 단계별 그림·수식 풀이·예시로 설명하되 글자 크기를 줄여 억지로 넣지 않는다.
- 이미지·수식·표·출처가 잘리지 않는지 확인한다. 부분 점수와 성공률, p50 latency와 전체 제어 지연을 구분한다.
- `pnpm build`와 프로젝트 base 경로 빌드를 확인한다. 결과 보고에는 실행한 검증만 쓴다.

## 보존과 공개

- 공부 기록, 원문, 슬라이드 소스, 피드백, 승인 기록은 자동 삭제하지 않는다.
- 재생성 가능한 `dist/`, `node_modules/`, `review/previews/`를 지식 원본으로 사용하지 않는다. 자동 정리 스케줄은 없다.
- 현재 작업은 로컬 HTML 개선과 Markdown 원본 정리다. Canva 작업은 취소됐으며 새 Canva 생성·편집을 진행하지 않는다.
- 현재 GitHub 저장소 생성·push·Pages 배포는 수행하지 않는다. 기존 게시 준비 안내와 패키지 도구가 있어도 공개 실행 허가로 해석하지 않는다. 사용자가 직접 게시하려는 결정을 보존한다.
- 공개 빌드의 `--without-notes`는 웹 결과물에서만 노트를 뺀다. 공개 Git 저장소에 커밋된 소스의 메모까지 숨기지 않는다.
- 현재 요청이 구조 준비라면 논문 내용이나 가상의 피드백·승인 내역을 채우지 않는다.

## 최신 결정과 과거 기록

- 이전 30장 제한과 JSON 편집 안내는 과거 구성의 기록이다. 최신 지시에 따라 페이지 수 제한 없이 설명의 순서와 이해를 우선한다.
- 원문 설명·저자 해석·우리 해석·예시·미해결은 문맥과 출처로 구분하되, 슬라이드 상단 우측의 분류 표지는 표시하지 않는다.
- 피드백의 반영 요청과 결과물 승인을 구분한다. MD 전환이나 인터랙션 구현 요청은 해당 결과의 검증·승인 완료를 뜻하지 않는다.

## 수식·글꼴 — 2026-11-05 사용자 변경

- 사용자 요청에 따라 수식 원본은 `$...$`·`$$...$$` LaTeX로 작성하고 KaTeX로 렌더링한다. 수식을 HTML sub/sup 조합으로 되돌리지 않는다.
- 한글 제목·본문·상세 해설은 나눔고딕을 사용한다. Regular/Bold/ExtraBold 원본 폰트를 수정 없이 유지하고 단일 HTML에 포함한다. 수학 기호에는 KaTeX 글꼴을 사용한다.
- 수식·글꼴 변경 뒤에는 실제 글리프 사용, 수식 렌더링·너비, 화면 넘침을 확인한다. 글자를 줄여 넘침을 감추지 않는다.

## 발표 조작 — 2026-11-05 사용자 변경

- 기본 조작은 PPT처럼 다음/이전 설명 단계와 슬라이드를 같은 방향키로 탐색한다. →/↓/PageDown/Space/Enter는 다음, ←/↑/PageUp/Backspace/Shift+Space는 이전이다.
- 이전 슬라이드가 단계 설명 장이면 마지막 단계로 들어가 역순으로 탐색한다. 매번 첫 단계로 초기화하지 않는다.
- Home/End는 처음/마지막 장, F는 전체 화면, Esc는 맨 위 팝업 닫기·전체 화면 종료다. 검색 입력과 버튼 고유 키 조작·그림 확대를 방해하지 않는다.
- 빈 슬라이드/본문 클릭은 다음 단계로 이동한다. 그림·상호작용 도식·버튼·링크·텍스트 선택은 고유 기능을 유지한다.
