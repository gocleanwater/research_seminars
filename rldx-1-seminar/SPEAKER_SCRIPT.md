## 04 · P002 · 기존 VLA의 문제

> 조작: 이 장은 5개 화면 상태로 설명한다. 이 장으로 직접 이동하면 1/5부터 시작한다. 아래 화살표 안내에 맞춰 한 번씩 넘긴다.

**화면 1/5 · VLA가 하는 일**

먼저 VLA가 무엇을 하는 모델인지 보겠습니다. 위의 흐름처럼 영상 관측과 언어 지시를 입력받아 로봇의 행동을 만드는 모델입니다. 예를 들어 “컵을 잡아”라는 지시를 받으면, 장면 속 컵을 보고 로봇이 어떻게 움직일지 정하는 것입니다.

그런데 장면과 지시의 의미를 잘 이해하는 것만으로는 실제 조작에서 부족한 경우가 있습니다. 세 가지 상황을 보겠습니다.

> 조작: →. 첫 번째 카드 ‘움직임’이 나타난다.

**화면 2/5 · 움직임**

그림처럼 컨베이어 벨트 위의 물체를 잡는 상황을 보겠습니다. 점선은 물체가 앞서 있던 위치이고, 물체는 벨트를 따라 오른쪽으로 이동했습니다. 그런데 손이 이전 위치를 향해 내려오면 물체를 놓칠 수 있습니다. 이렇게 움직임을 읽는 능력이 부족하면, 물체의 위치를 알아도 움직이는 대상에 맞춰 행동하기 어렵습니다.

> 조작: →. 두 번째 카드 ‘기억’이 나타난다.

**화면 3/5 · 기억**

이번에는 공을 컵으로 가린 뒤 컵을 섞는 야바위 상황입니다. 공을 어느 컵에 숨겼는지 보고, 이후 컵이 어떻게 이동했는지도 기억해야 합니다. 지금 보이는 컵들의 모양만으로는 공이 어디 있는지 알 수 없기 때문입니다. 이렇게 과거를 기억하는 능력이 부족하면 올바른 컵을 고르기 어렵습니다.

> 조작: →. 세 번째 카드 ‘물리 센싱’이 나타난다.

**화면 4/5 · 물리 센싱**

마지막은 물리 센싱입니다. 힘과 접촉, 미끄러짐 같은 물리적 상태를 감지하는 능력입니다. 영상에서 보이는 모습만으로는 이런 상태를 충분히 알기 어려울 수 있습니다. 화면의 집기 그림은 이 정보가 왜 필요한지 보여주는 예시입니다. 약하게 잡으면 물체를 놓치고, 너무 세게 잡으면 손상될 수 있기 때문입니다. 촉각과 토크 같은 물리 신호로 상태를 파악하고, 그 정보를 적절한 힘 조절에 활용하는 것입니다. 물리 센싱은 상태를 감지하는 능력이고, 힘 조절은 그 정보를 사용하는 조작의 예시로 구분하겠습니다.

> 조작: →. 세 가지 카드를 함께 강조한 정리 화면으로 이동한다.

## 05 · P105 · RLDX-1 Architecture

다음은 RLDX-1의 구조입니다. Figure 3에서 각 모듈과 정보의 흐름을 따라가 보겠습니다.

## 06 · P032 · RLDX-1 Architecture

> 조작:이 장 안의35개 화면 상태를 →/←로 넘긴다. 작은 원문 그림으로 현재 위치를 확인하며 오른쪽 설명과 도식을 따라 말한다.

### 단계 01/35 · 전체 구조

왼쪽은 영상과 언어에서 특징을 만드는 VLM이고, 오른쪽은 행동을 생성하는 MSAT입니다. 아래 Memory Module은 이전에 계산한 특징을 보관하고 읽습니다. 영상이 들어와서 어떤 정보를 거친 뒤 행동이 되는지, 왼쪽부터 따라가겠습니다.

### 단계 02/35 · Vision Encoder 확대

먼저 Vision Encoder입니다. 한 장의 사진만 보는 것이 아니라 여러 시점의 관측을 함께 받습니다. 실제 pre-training에서는 현재를 기준으로 −6, −4, −2, 0의 네 시점 관측을 사용합니다. 이를 통해 물체의 현재 모습과 앞서 어떻게 움직였는지를 함께 볼 수 있습니다.

### 단계 03/35 · 첫 화살표: 1–9층

Vision Encoder는 총 27개 ViT 층으로 구성됩니다. 먼저 1–9층이 영상의 시각 특징을 추출하고, 9층 뒤에 움직임 정보를 명시적으로 추출하는 Motion Module을 넣습니다. 약 30% 깊이에서 물리적 단서가 풍부하다는 선행 관찰을 참고한 위치입니다.

### 단계 04/35 · 두 번째 화살표: Motion Extractor

Motion Extractor에서는 STSS, Space-Time Self-Similarity을 계산합니다. 각 특징과 주변 위치·인접 시점 특징의 correlation을 계산하고, 그 결과를 encoder로 처리해 움직임 특징을 만듭니다.

직관적으로 공이 지금 같은 위치에 있더라도, 이전에 왼쪽에 있었는지 오른쪽에 있었는지에 따라 이동 방향이 다르겠죠. 프레임 사이에 비슷한 특징이 어디에 나타나는지를 움직임의 단서로 활용하는 것입니다.

### 단계 05/35 · 세 번째 화살표: Residual addition

추출한 움직임 특징을 기존 시각 특징에 더합니다. 이것이 residual update입니다. 기존 시각 표현을 바탕으로 움직임 정보를 보정해서 넣는다고 이해하면 됩니다. 여기의 덧셈은 같은 위치와 차원을 맞춘 원소별 덧셈이므로 특징의 shape는 유지됩니다.

### 단계 06/35 · 네 번째 화살표: 10–27층

움직임 정보가 더해진 특징은 나머지 10–27층에서 계속 처리합니다. 이렇게 얻은 영상 특징 토큰이 다음 VLM으로 넘어갑니다. 여러 프레임 입력은 pre-training부터 사용하고, 이 STSS 모듈은 뒤의 mid-training에서 추가한다는 점도 기억해 두겠습니다.

### 단계 07/35 · 전체 그림으로 복귀

지금까지는 영상에서 움직임을 반영한 시각 특징을 만드는 과정이었습니다. 이제 이 특징이 언어 지시와 함께 처리되는 VLM 부분을 보겠습니다.

### 단계 08/35 · VLM 확대

이 부분은 영상과 언어를 함께 처리하는 VLM입니다. Qwen3-VL 8B를 로봇 VQA로 추가 학습한 RLDX-1-VLM을 사용합니다. 특징이 흘러가는 경로를 보기 전에, 이 모델을 왜 추가 학습했는지 같은 그림 안에서 먼저 설명하겠습니다.

### 단계 09/35 · 로봇 VQA

컵을 알아보는 데서 더 나아가, 로봇이 조작하려면 물체와 손의 위치, 지금 할 작업, 구체적인 동작을 함께 이해해야 합니다. 저자들은 이런 내용을 질문과 답으로 만들어 VLM을 추가 학습합니다. 이것이 로봇 VQA입니다.

화면 왼쪽부터 보면, 손끝과 물체가 어떤 위치 관계에 있는지 묻습니다. 그다음에는 목표를 이루기 위해 지금 해야 할 작업을 묻고, 마지막으로는 그 장면에서 로봇이 어떤 동작을 하는지 묻습니다.

이런 질문과 답으로 Qwen3-VL 8B를 추가 학습한 모델이 RLDX-1-VLM입니다. 이 모델에서 조작에 필요한 특징을 뽑아 행동 모델에 전달합니다. 다음에는 그 특징을 만들 때 어떤 토큰을 입력하는지 보겠습니다.

### 단계 10/35 · 첫 화살표: 세 종류의 입력 토큰

보라색은 영상 토큰, 연한 초록색은 언어 토큰, 청록색은 cognition tokens입니다. 세 묶음을 이어 붙여 VLM에 넣습니다. Cognition tokens는 64개의 학습 가능한 query token입니다.

처음부터 완성된 인지 정보가 들어 있는 것은 아닙니다. Transformer의 attention을 거치면서 영상과 언어를 참고하고, 행동 예측에 필요한 정보를 모으는 위치로 학습됩니다.

### 단계 11/35 · 두 번째 화살표: 초반 1–4층

초반 1–4층에서는 여러 프레임을 함께 처리하며 시간 맥락을 모읍니다. 이때 Qwen3-VL의 DeepStack 구조를 활용합니다.

DeepStack은 Vision Encoder의 여러 층에서 뽑은 정보를 LLM의 초반층에 나누어 전달하는 구조입니다. LLM이 장면을 해석하는 동안, 이미지에서 얻은 정보를 처리 단계마다 더해 주는 셈입니다.

저자들은 각 프레임에 이 시각 정보를 반영할 수 있도록, 초반 4층까지는 과거 프레임을 그대로 유지합니다. 이 과정을 거친 다음 과거 프레임 정보를 하나로 압축해, 이후 층의 계산량을 줄입니다. 화면 아래처럼 시각 특징 반영, 과거 프레임 압축, 적은 토큰으로 계산하는 순서입니다. 다음은 이 압축을 어떻게 하는지 보겠습니다.

### 단계 12/35 · 세 번째 화살표: 과거 프레임 압축

4층 뒤에서는 과거 관측 위치의 hidden states를 Average Pooling해 context token 하나로 압축합니다. 현재 관측, 언어 지시, cognition tokens는 유지합니다. 이후 층에서 처리할 토큰 수를 줄이기 위한 설계입니다.

### 단계 13/35 · 네 번째 화살표: Cognition features

중간층에서 cognition token 위치에 해당하는 출력 특징만 가져옵니다. 이것이 $\mathbf h_t$입니다. 입력 토큰을 붙였다고 바로 $\mathbf h_t$가 되는 것이 아니라, 영상과 언어를 참고해 갱신된 해당 위치의 hidden vectors를 선택하는 것입니다.

64개 cognition 위치의 특징을 행동 모델에 전달합니다. 다른 위치의 출력도 내부 계산에는 기여했지만, 행동 모델로 넘기는 출력은 이 cognition features로 정리합니다. 왜 중간층을 택했는지는 뒤의 ablation에서 확인하겠습니다.

### 단계 14/35 · 전체 그림으로 복귀

이제 현재 관측과 지시에서 $\mathbf h_t$가 만들어졌습니다. 하지만 짧은 관측 구간보다 더 이전에 일어난 사건이 필요할 수 있습니다. 그 역할을 Memory Module이 맡습니다.

### 단계 15/35 · Memory Module 확대

예를 들어 물체를 어느 상자에 넣었는지 본 뒤 상자가 가려지면, 현재 영상만으로는 선택할 수 없습니다. 그래서 이전에 계산한 cognition features를 저장해 두고 현재 특징과 함께 읽습니다. 과거 영상 전체를 매번 다시 처리하는 대신 특징을 활용하는 방식입니다.

### 단계 16/35 · 첫 화살표: 과거 특징 Queue

아래 줄의 $\mathbf Q_t$가 과거 cognition features를 보관하는 queue입니다. Mid-training 설정에서 사용하는 과거 특징의 간격은 ALLEX가 40 timestep, Franka가 16 timestep입니다. 두 로봇 모두 과거 세 시점의 특징 묶음을 사용합니다.

한 시점에 64개이므로 과거 부분에는 $3\times64=192$개의 특징 벡터가 있습니다.

### 단계 17/35 · 두 번째 화살표: 현재 특징 연결

과거 queue에 현재 $\mathbf h_t$를 토큰 방향으로 이어 붙여 Memory Transformer에 넣습니다. 과거 세 묶음과 현재 한 묶음이 함께 들어가는 것입니다. 이때는 concat이므로 토큰의 개수가 늘어납니다.

### 단계 18/35 · 세 번째 화살표: Causal Transformer

Memory Transformer도 causal attention으로 시간 순서를 유지합니다. 뒤쪽 시점은 자기 자신과 앞선 이력을 읽고, 이를 통해 memory features인 $\mathbf m_t$를 만듭니다. 현재 판단에 과거 사건의 정보를 반영하는 과정입니다.

### 단계 19/35 · 네 번째 화살표: $\mathbf h_t$와 $\mathbf m_t$ 연결

현재 특징 $\mathbf h_t$와 memory 특징 $\mathbf m_t$를 이어 붙여 행동 모델의 C stream으로 전달합니다. 본문의 [$\mathbf h_t$, $\mathbf m_t$] 표기에 따라 토큰 방향의 concat으로 이해하겠습니다.

### 단계 20/35 · 전체 그림으로 복귀

여기까지가 행동 생성에 사용할 인지·기억 특징을 만드는 경로입니다. 이제 이 특징과 현재 로봇 상태, 물리 센서 정보를 함께 읽는 MSAT를 보겠습니다.

### 단계 21/35 · MSAT 확대

MSAT는 Multi-Stream Action Transformer입니다. 성격이 다른 정보를 각각의 stream에서 처리하면서 joint self-attention으로 정보를 교환합니다. 지금 그림은 물리 신호가 있는 경우여서 P·C·A의 세 stream을 보여줍니다.

### 단계 22/35 · 첫 화살표: P stream

P는 physics stream입니다. 현재 측정한 촉각·토크 신호와, 앞으로의 물리 신호를 예측하기 위한 noisy 미래 후보가 들어갑니다. 접촉 부위가 가려지거나 힘의 차이가 중요한 작업에서 이런 신호를 활용합니다. 센서가 없는 경우에는 P stream의 attention을 mask할 수 있습니다.

### 단계 23/35 · 두 번째 화살표: C stream

C stream에는 앞에서 만든 현재 cognition features와 memory features가 들어갑니다. 무엇을 보고 있고 어떤 지시를 받았는지, 과거에 어떤 일이 있었는지를 행동 생성의 조건으로 제공하는 부분입니다.

### 단계 24/35 · 세 번째 화살표: A stream

A stream에는 현재 로봇 상태와 noisy action chunk가 들어갑니다. 현재 상태는 로봇이 지금 어떤 자세인지 알려주고, noisy action chunk는 모델이 다듬어 갈 미래 행동 후보입니다. 후보를 어떻게 만들고 갱신하는지는 뒤의 수식 장에서 설명하겠습니다.

### 단계 25/35 · 초반 블록은 세 경로로 처리한다

이제 MSAT 안에서 정보가 어떻게 함께 쓰이는지 보겠습니다. 초반 블록에서는 인지 C, 행동 A, 물리 신호 P를 각자의 경로로 처리합니다. 그렇다고 세 경로가 따로 판단하는 것은 아닙니다. 가운데 joint attention에서 서로 필요한 정보를 참고합니다. 다음 그림으로 그 뜻을 보겠습니다.

### 단계 26/35 · 서로 참고하되, 각자의 자리는 유지한다

초록색 C는 장면과 기억, 보라색 A는 행동, 파란색 P는 물리 신호의 토큰 자리입니다. 가운데 joint attention에서 서로의 정보를 참고합니다.

보라색 행동 토큰을 따라가 보겠습니다. C의 장면·기억과 사용 가능한 P의 접촉 정보를 참고하면, 오른쪽의 같은 A 자리에 그 정보가 반영된 특징이 나옵니다. C와 P도 각각 자기 자리에 대응하는 출력을 얻습니다. 유지되는 것은 토큰의 자리와 묶음, 경로별 전용 처리이고, 토큰에 담긴 특징값은 갱신됩니다. 이 특징은 최종 로봇 명령이 아니라 이후 행동 생성에 쓰는 내부 표현입니다.

### 단계 27/35 · 다섯 번째 화살표: Double-stream blocks

뒤쪽 Double-stream blocks에서는 C와 A의 token sequence를 concat해 하나의 stream으로 처리합니다. P stream은 별도로 유지하며, 합쳐진 C-A stream과 attention으로 정보를 주고받습니다.

### 단계 28/35 · 여섯 번째 화살표: 변화율과 반복 갱신

한 번의 forward에서 얻는 것은 미래 후보를 어느 방향으로 얼마나 바꿀지 나타내는 변화율입니다. 그 값으로 후보를 갱신하고, 같은 조건을 참조하면서 다시 MSAT를 통과시킵니다. 각 denoising 단계에서 Triple-stream과 Double-stream blocks를 모두 거칩니다.

이 반복이 끝나면 최종 미래 행동과 물리 신호를 얻습니다. 잠시 뒤 같은 그림에서 학습과 갱신 과정을 나누어 풀어보겠습니다. 조건인 $\mathbf{h}_t$, $\mathbf{m}_t$, 현재 상태와 센서는 유지하고, noisy 미래 후보가 갱신되는 과정입니다.

### 단계 29/35 · Flow matching policy의 학습 경로

이제 이 행동 정책을 어떻게 학습하는지 보겠습니다. RLDX-1은 flow matching을 사용해 노이즈에서 행동 묶음을 생성하는 정책입니다. 앞에서 본 MSAT는 이 과정에 필요한 변화율을 예측하는 모델입니다.

화면의 식은 노이즈와 정답 행동을 비율에 따라 섞어서, 학습에 사용할 행동 후보를 만드는 식입니다. 먼저 $\mathbf a$는 시연에서 얻은 정답 action chunk입니다. $\boldsymbol\epsilon$은 이 행동 묶음과 같은 크기로 뽑은 표준 정규 노이즈입니다.

여기서 $t$는 행동의 시점이고, $\tau$는 후보를 다듬는 denoising 진행도입니다. 학습할 때는 0과 1 사이의 $\tau$를 하나 고르고, 정답 행동에는 $\tau$를, 노이즈에는 $1-\tau$를 곱해 더합니다. 그래서 $\tau=0$이면 노이즈만 남고, $\tau=1$이면 정답 행동만 남습니다. 그 사이에서는 두 값이 섞인 후보가 만들어집니다. 이 후보가 왼쪽의 $\mathbf a^\tau$입니다.

이렇게 노이즈에서 정답 행동까지 이어지는 직선 경로를 준비합니다. 다음에는 이 경로에서 MSAT가 무엇을 정답으로 배우는지 보겠습니다.

### 단계 30/35 · 정답 변화율과 MSAT 예측

앞에서 만든 행동 후보의 경로를 이번에는 $\tau$에 대해 미분해 보겠습니다. 화면의 식은 진행도에 따른 행동 후보의 변화율을 구하는 식입니다. 계산하면 $\mathbf a-\boldsymbol\epsilon$이 나오고, 이 값을 정답 변화율 $\mathbf v^*$라고 둡니다.

이 값을 학습의 정답으로 쓰는 이유는 앞에서 만든 경로의 성질에 있습니다. $\tau$가 $0$에서 $1$로 커질수록 후보 $\mathbf a^\tau$는 노이즈에서 정답 행동으로 가까워집니다. 따라서 이 경로를 미분한 값은 후보를 정답 행동 쪽으로 어느 방향으로 얼마나 바꿔야 하는지를 나타냅니다. 우리가 정한 경로에서 이 변화율을 계산할 수 있으므로, MSAT가 맞힐 정답으로 사용하는 것입니다.

아래 흐름에서는 MSAT를 함수 $\mathbf u_\theta$로 나타냈습니다. 후보 $\mathbf a^\tau$, 진행도 $\tau$, 조건 $\mathbf c_t$를 넣으면 예측 변화율 $\mathbf u_\theta(\mathbf a^\tau,\tau,\mathbf c_t)$가 나옵니다. 화면에서는 이 예측값을 $\widehat{\mathbf v}$로 표시했습니다. 조건 $\mathbf c_t$는 현재 인지 특징과 기억, 로봇 상태, 사용 가능한 센서 정보입니다.

학습에서는 이 예측 변화율 $\widehat{\mathbf v}$를 방금 계산한 정답 변화율 $\mathbf v^*$와 비교합니다. 다음에는 두 값의 차이를 어떤 loss로 계산하는지 보겠습니다.

### 단계 31/35 · 예측과 정답의 차이를 줄여 학습한다

그렇다면 모델이 정답 변화율을 얼마나 잘 맞혔는지는 어떻게 볼까요? 화면의 식은 그 차이를 계산하는 학습 loss입니다.

왼쪽 항 $\mathbf u_\theta(\mathbf a^\tau,\tau,\mathbf c_t)$는 MSAT가 예측한 변화율이고, $\mathbf v^*$는 앞에서 구한 $\mathbf a-\boldsymbol\epsilon$입니다. 두 값의 차이를 구한 뒤, 각 성분의 차이를 제곱해서 더합니다. 식의 $\lVert\cdot\rVert_2^2$는 이 계산을 뜻합니다. 예측이 정답에 가까울수록 loss가 작아집니다.

학습할 때는 이 loss가 줄어들도록 모델의 가중치 $\theta$를 바꿉니다. 노이즈와 정답 사이의 경로에서 필요한 변화율을 이렇게 배우는 것이 flow matching입니다. 이제 학습된 모델로 실제 행동을 만들 때를 보겠습니다.

### 단계 32/35 · 추론은 학습한 변화율로 후보를 갱신한다

추론할 때는 정답 행동을 모르기 때문에, 랜덤 노이즈를 첫 후보로 놓습니다. 화면의 식은 학습한 변화율을 사용해 다음 행동 후보를 만드는 Euler 갱신식입니다.

오른쪽 첫 항은 지금의 후보입니다. 여기에 MSAT가 예측한 변화율을 바로 더하는 것이 아니라, 이번에 진행할 간격 $\Delta\tau_i$를 곱해서 더합니다. $\Delta\tau_i$는 다음 진행도와 현재 진행도의 차이입니다. 변화율에 이 간격을 곱한 값이 이번에 후보를 바꿀 양이 되고, 왼쪽 항이 그렇게 얻은 다음 후보입니다.

새 후보를 다시 MSAT에 넣고 같은 계산을 반복해서, 진행도 $\tau$가 $1$에 도달하면 생성한 행동 묶음을 얻습니다. 한 묶음을 만드는 동안 현재 관측 조건과 모델 가중치는 유지하고, 행동 후보를 갱신합니다. 학습에서는 정답 변화율로 모델을 가르쳤고, 여기서는 학습된 모델의 예측을 사용해 행동을 만드는 것입니다.

### 단계 33/35 · 미래 물리 신호도 같은 방식으로 학습한다

미래 물리 신호도 action과 같은 방식으로 학습하고 추론합니다. 화면의 왼쪽 식에서 $\mathbf a$가 들어간 자리에 오른쪽 식의 $\mathbf p_f$가 대응한다고 보시면 됩니다. 따라서 MSAT는 미래 행동과 미래 물리 신호의 변화율을 함께 예측합니다.

### 단계 34/35 · Closed-loop 제어

미래 행동 묶음을 만들었다고 해서 전부 끝까지 실행해야 하는 것은 아닙니다. Appendix C의 RL 설정에서는 40개를 생성하고 앞의 20개만 실행한 뒤 새 관측으로 정책을 다시 호출합니다. 그사이에 환경이 바뀌었을 수 있으므로 남은 계획을 그대로 밀어붙이기보다 새 상황에 맞는 chunk를 만들 기회를 주는 것입니다. 이 40과 20은 해당 설정의 값이고 모든 benchmark에 동일하게 적용되는 규칙은 아닙니다.

### 단계 35/35 · 전체 경로 정리와 다음 장 연결

전체 경로를 다시 보겠습니다. 영상과 지시에서 cognition을 만들고, 과거 특징에서 memory를 얻습니다. 이 정보와 현재 로봇 상태·센서를 조건으로 MSAT가 행동 후보를 반복 갱신합니다. 일부 행동을 실행한 뒤 다시 관측하는 바깥 반복까지 연결됩니다. 여기까지 모델이 어떻게 움직이는지 봤으니, 다음은 이 모델을 학습시키는 데이터가 어디서 오는지 살펴보겠습니다.

## 07 · P106 · Training Data

## 08 · P013 · 학습 데이터

모델의 구조를 봤으니, 이제 무엇으로 학습시키는지 보겠습니다. 보고서의 데이터는 공개 실제 데이터, 자체 실제 데이터, 합성 데이터로 나누어 볼 수 있습니다.

공개 실제 데이터는 여러 로봇이 이미 수행한 시연을 모은 것입니다. 다양한 몸체와 작업에서 공통으로 쓰이는 조작의 기본기를 배우는 재료입니다. 자체 실제 데이터는 ALLEX와 Franka로 직접 모은 경험입니다. 목표 로봇에 맞추고, 기억과 토크·촉각 같은 새 기능을 학습시키는 데 사용합니다.

합성 데이터는 직접 많이 모으기 어려운 경험을 늘리는 방법입니다. 실제 시연을 바탕으로 작업 지시와 장면을 바꾸고, 새 영상에 행동 라벨을 붙여 학습 쌍을 만듭니다. 따라서 특정 작업에만 쓰는 데이터라는 뜻은 아닙니다. 실제로 합성 GR-1 데이터는 Pre-training에, 합성 ALLEX 데이터는 Mid-training에도 들어갑니다.

여기까지 공개·자체 데이터의 역할을 짚었고, 다음부터는 합성 데이터를 어떻게 만들고 걸러서 사용하는지 따라가 보겠습니다.

## 09 · P072 · 합성 데이터 생성

합성 데이터를 만드는 이유는 특수한 로봇의 시연을 대량으로 수집하기 어렵기 때문입니다. 보고서는 공개 GR-1 시연과 자체 ALLEX 시연을 바탕으로 경험을 늘립니다.

Figure 4의 위쪽을 먼저 보겠습니다. 실제 시연의 시작 장면과 작업 지시를 바탕으로 새로운 로봇 영상을 만듭니다. 이때 사용하는 영상 생성 모델도 로봇 시연으로 추가 학습해 준비합니다. 이 모델의 학습과, 나중에 이 데이터로 RLDX-1 정책을 학습하는 것은 서로 다른 과정입니다.

새 영상만으로는 로봇을 학습시키기 어렵습니다. 로봇이 어떻게 움직여야 하는지에 해당하는 행동 라벨이 필요하기 때문입니다. 그래서 IDM, 즉 inverse dynamics model이 영상의 현재와 미래 관측에서 행동 묶음을 추정합니다.

아래쪽은 검증 과정입니다. 영상이 그럴듯한지, 추정한 행동을 실제로 재생했을 때 영상과 움직임이 맞는지 확인합니다. 통과한 영상과 행동을 학습 쌍으로 사용합니다. 먼저 위쪽의 Task·Scene 변형부터 보겠습니다.

## 10 · P014 · Task·Scene Augmentation

같은 시작 장면과 지시로 영상을 만들면 원래 시연과 너무 비슷한 결과가 나올 수 있습니다. 그래서 두 가지를 바꿉니다. 무엇을 할지 정하는 Task와, 어떤 장면에서 할지 정하는 Scene입니다.

Figure 5의 첫 행은 원본 시연입니다.

두 번째 행은 작업 지시를 바꾼 예입니다. 지시를 동작·물체·놓을 위치·어느 손이라는 요소로 나누어 재조합하거나, 원래의 집기·따르기·밀기 같은 skill을 조건으로 실행 가능한 지시를 만듭니다. Figure 5를 다시 보시면, 원본의 신라면을 쌓는 동작이 두 번째 행에서는 책상 위 신라면을 트레이로 옮기는 동작으로 바뀐 것을 볼 수 있습니다.

세 번째 행은 장면을 바꾼 예입니다. 시작 이미지를 편집하고, 그 이미지에서 새 영상을 생성합니다. 테이블, 물체, 조명, 배경 같은 조건을 다양화할 수 있습니다.

이때 원본 장면의 윤곽을 추출한 Canny edge map을 함께 제공합니다. 생성 모델이 손과 물체의 배치 같은 장면 구조를 참고하면서 외관을 바꾸도록 돕는 안내선입니다.

Figure 5의 세 번째 행을 보시면 컵라면이 초록색 컵으로 바뀌었고, 조명의 세기와 책상의 질감·색깔도 달라진 것을 볼 수 있습니다.

이처럼 시작 장면을 바꾸는 방법에 더해, 생성된 영상의 동작을 유지하면서 색과 질감을 바꾸는 V2V 변형도 사용합니다. 이렇게 변형한 영상이 학습에 쓸 만큼 타당한지, 다음에 검증합니다.

## 11 · P015 · 합성 데이터 검증

생성된 영상과 IDM의 행동 라벨을 바로 정답으로 쓰지는 않습니다. 두 가지를 확인합니다.

첫 번째는 영상 품질입니다. VLM으로 지시와 실제 영상의 행동이 맞는지, 손의 접근 거리나 물체 접촉이 그럴듯한지 봅니다. 지시와 다르게 움직였으면 관찰된 행동에 맞춰 설명을 고치고, 움직임의 타당성 기준을 통과한 영상을 남깁니다.

두 번째는 행동 일관성입니다. 오른쪽의 A는 합성 영상입니다. IDM이 이 영상에서 행동을 추정하고, 그 행동을 시뮬레이터에서 실행하면 B라는 rollout 영상이 나옵니다. Rollout은 추정 행동을 실행해 얻은 결과 영상입니다.

이제 A와 B의 움직임이 맞는지 비교합니다. 영상은 그럴듯해도 행동 라벨이 틀리면, 같은 동작이 재현되지 않을 수 있습니다. 움직임 일치도가 높은 영상·행동 쌍만 학습에 사용합니다. 다음에는 이 일치 판정 기준을 어떻게 학습하는지 보겠습니다.

## 12 · P047 · 움직임 일치 검사기

움직임 일치 검사기는 합성 영상과, 그 영상에서 IDM이 추정한 action을 시뮬레이터에서 실행해 만든 rollout 영상의 움직임을 비교하는 모델입니다.

이 검사기의 판단 기준은 실제 시연과 그 시연의 정답 action을 이용해 학습합니다.

왼쪽은 일치하는 쌍입니다. 실제 시연 영상과, 그 시연의 정답 행동을 시뮬레이터에서 재생한 rollout 영상을 짝짓습니다. 실제와 시뮬레이션의 외관은 달라도 같은 행동에 대응하는 움직임을 갖습니다.

오른쪽은 어긋나는 쌍입니다. 같은 episode에서 시간 구간을 밀어 짝짓거나, 같은 작업 지시를 가진 다른 episode와 짝짓습니다. 작업 이름이 같아도 손과 물체가 움직이는 구체적인 시점과 경로는 다를 수 있다는 점을 배우게 합니다.

영상 특징을 만드는 V-JEPA2는 고정하고, 그 위의 작은 판정기를 학습합니다. 이렇게 실제 시연으로 배운 기준을 앞의 합성 영상·IDM 행동 쌍에 적용합니다. 여기까지가 학습 데이터를 만드는 과정이고, 이제 이 데이터를 사용해 RLDX-1을 어떻게 학습시키는지 보겠습니다.

## 14 · P035 · 학습 단계

이제 데이터를 준비했으니, 모델을 어떤 순서로 학습시키는지 보겠습니다. 세 단계는 각각 배우는 목적이 다릅니다.

Pre-training은 여러 로봇의 경험에서 범용 조작 정책을 만드는 단계입니다. Mid-training은 그 정책을 ALLEX와 Franka에 맞추고, 움직임·기억·물리 센싱 기능을 더하는 단계입니다. Post-training은 실제로 수행할 목표 작업에 적응하는 단계입니다.

앞의 데이터 종류와 이 단계를 일대일로 대응시키지는 않습니다. 공개·자체·합성은 학습 재료를 구분하는 말이고, 여기서는 재료를 섞어 무엇을 배우는지를 구분합니다. 각 단계가 이전 정책을 어떻게 바꾸는지 차례로 보겠습니다.

## 15 · P016 · Pre-training

Pre-training에서는 여러 로봇에서 공통으로 쓰는 조작의 기본기를 배웁니다. 왼쪽의 데이터는 공개 실제 데이터와 합성 GR-1 데이터입니다. 그리퍼, 양팔, 다섯 손가락 휴머노이드처럼 다양한 몸체의 관측과 행동을 학습 경험으로 사용합니다.

가운데의 flow matching은 관측과 지시를 조건으로, 시연 행동을 향하는 변화율을 예측하도록 학습하는 과정입니다. 다양한 로봇과 작업의 경험을 통해 공통적인 행동 예측 능력을 배우는 것입니다.

이렇게 배운 범용 policy를 출발점으로, 다음 Mid-training에서 ALLEX와 Franka에 맞추고 움직임·기억·물리 센싱 기능을 더합니다.

## 16 · P017 · Mid-training

Mid-training에서는 범용 policy를 ALLEX와 Franka의 몸체와 제어에 맞추면서, 움직임·기억·물리 센싱 기능을 더합니다.

먼저 왼쪽의 데이터 조합을 보겠습니다. ALLEX는 직접 수집한 시연과 합성 ALLEX 데이터를 함께 사용합니다. Franka는 공개 실제 데이터인 DROID와 직접 수집한 시연을 함께 사용합니다. 새로 사용하는 memory·torque·Franka tactile 입력의 supervision은 직접 시연에서 제공합니다.

오른쪽은 함께 학습하는 기능입니다. STSS로 움직임 정보를 반영하고, Memory Module과 P stream을 추가해 과거 경험과 물리 신호를 활용하게 합니다.

아래 순서처럼 기존 모델을 고정한 상태에서 새 모듈을 먼저 학습한 뒤, 전체를 함께 학습합니다. 이렇게 목표 로봇과 새 기능에 맞춘 policy를 다음 Post-training에서 특정 작업에 적응시킵니다.

## 17 · P018 · Post-training

Post-training에서는 실제로 수행할 목표 작업에 맞춰 policy를 학습합니다. 사용하는 데이터는 해당 로봇으로 직접 수집한 작업별 시연입니다. 이 시연을 이용한 Imitation Learning, IL이 보고서의 거의 모든 실험에서 기본이 됩니다.

화면의 첫 단계에서 작업의 기본 동작 순서를 정하고 시연을 모읍니다. 잡는 자세나 실행 순서처럼 일관되게 유지할 요소와, 물체 위치처럼 다양하게 보여 줄 요소를 구분합니다. 그 시연으로 policy를 학습한 다음 실제 작업을 수행시킵니다.

실행에서 실패 조건을 찾으면 그 조건의 시연을 추가해 다시 학습합니다. 예를 들어 특정 물체 위치에서 실패했다면, 그 위치 범위를 포함하도록 시연을 늘립니다. 이 반복으로 부족한 작업 경험을 보완합니다.

일부 고난도 정밀 조작에서는 실제 로봇을 실행해 얻은 rollout을 추가로 수집하고, RECAP 기반 RL로 더 개선합니다. 다음에는 이 과정에서 policy와 critic이 어떤 역할을 하는지 보겠습니다.

## 18 · P019 · RECAP

RECAP에서는 행동을 만드는 policy와 평가하는 critic의 역할을 나눕니다. Policy는 RLDX-1이고, critic은 현재 작업이 얼마나 진행됐는지 가치로 평가하는 별도 모델입니다.

먼저 시연 데이터로 critic을 학습하고, 그 평가에서 advantage 라벨을 만듭니다. Policy는 이 라벨을 조건으로 시연 데이터를 학습합니다. Critic이 다음 관절 명령을 직접 내려 주는 구조는 아닙니다.

그다음 현재 policy를 실제로 실행해 rollout을 모으고 기존 데이터에 합칩니다. 누적 데이터 중 성공한 경험으로 critic을 갱신하고, 전체 데이터의 라벨을 다시 생성해 policy를 재학습합니다. 이 과정을 반복하며 실행 경험을 추가합니다.

보고서는 이 평가 모델에 기존 VLM의 숫자 텍스트 출력을 활용합니다. 다음 Figure 8에서는 이 critic이 진행과 실패, 회복을 어떻게 평가하는지 보겠습니다.

## 19 · P037 · Critic의 진행 평가

Figure 8은 큐브를 옮기는 두 trajectory에서 critic의 평가가 어떻게 변하는지 보여 줍니다. 파란색은 새 예측 head로 value 분포를 내는 방식이고, 초록색은 이 보고서처럼 기존 VLM의 숫자 텍스트 출력으로 value를 내는 방식입니다.

먼저 왼쪽의 첫 시도 성공 사례를 보겠습니다. 초록 곡선은 작업이 진행될수록 비교적 꾸준히 올라갑니다. 오른쪽은 실패 후 다시 시도해 성공한 사례입니다. 실패할 때 값이 내려갔다가, 작업을 회복하면서 다시 올라가는 모습을 봅니다.

이런 평가가 실제 작업의 진행을 따라가면 앞의 policy 학습에 사용할 신호가 됩니다. 다만 세로축은 normalized value이지 성공률이 아니며, 이 두 예시만으로 모든 작업의 critic 정확도를 확정할 수는 없습니다. 여기까지가 데이터를 준비하고 목표 작업의 정책으로 다듬는 과정입니다. 마지막으로 Part 1의 핵심을 정리하겠습니다.

## 20 · P096 · Part 1 최종 정리

Part 1에서 본 내용을 하나로 연결해 보겠습니다. 출발점은 실제 조작에는 지금 보이는 물체를 알아보는 것 외에도, 움직임을 읽고 과거를 기억하며 물리적 상태를 감지하는 능력이 필요하다는 것이었습니다.

구조로 보면 영상과 언어에서 조작에 필요한 특징을 만들고, 과거의 특징을 Memory에서 가져옵니다. MSAT는 이 정보와 현재 로봇 상태, 사용 가능한 센서 신호를 조건으로 미래 행동 묶음을 생성합니다. 생성한 행동의 일부를 실행한 뒤에는 새 관측으로 다시 판단합니다.

이 모델을 가르치는 재료는 공개 시연, 자체 수집 시연, 그리고 검증한 합성 데이터입니다. 학습은 여러 로봇의 경험으로 기본기를 쌓는 Pre-training, 목표 로봇과 움직임·기억·센서 기능에 맞추는 Mid-training, 실제 작업에 적응하는 Post-training으로 이어집니다. 마지막 단계의 기본은 시연 기반 IL이고, 어려운 일부 작업에는 RECAP 기반 RL을 보완합니다. 이때 critic은 작업이 얼마나 진행됐는지를 평가하는 역할입니다.

따라서 Part 1의 핵심은 모델 구조, 데이터, 학습이 하나의 조작 정책을 만드는 과정으로 이어진다는 것입니다.

## 27 · P020 · CUDA Graph

**화면 1/2 · 학습 때와 배포 때**

학습할 때는 입력 데이터의 구성에 따라 RoPE의 위치 관련 준비값과 attention mask 구조가 달라질 수 있습니다. 토큰 수와 위치 배치, 어느 정보를 읽을 수 있는지에 맞춰 준비해야 하기 때문입니다. 반면 배포할 때는 정해진 입력 구성으로 추론을 반복하므로, 이 설정을 고정할 수 있습니다. 그러면 같은 준비값을 매번 다시 계산할 필요가 없습니다.

저자들은 추론할 때마다 하던 준비 계산을 미리 해 두고 재사용하도록 했습니다. 이렇게 하면 나뉘어 있던 GPU 작업을 하나의 CUDA Graph로 묶을 수 있고, 여러 번 launch할 때마다 드는 시간을 줄일 수 있습니다.

**화면 2/2 · CUDA Graph 실행 비교**

Figure 9의 위쪽을 보면 Graph 1을 launch해서 A와 B를 실행하고, C와 D를 실행하려면 Graph 2를 다시 launch합니다. 아래쪽은 A부터 D까지 하나의 graph로 묶어 한 번만 launch합니다. 오른쪽 Speed Up이 이렇게 반복되는 launch 부담을 줄여 얻은 시간 차이입니다.

## 28 · P038 · Kernel Fusion

**화면 1/2 · Kernel Fusion 전후**

다음은 Kernel Fusion입니다. CUDA Graph가 GPU 작업을 호출하는 부담을 줄였다면, 여기서는 연산 사이의 메모리 이동을 줄입니다.

위쪽처럼 연산을 나눠 실행하면 RMSNorm의 결과를 global memory에 저장하고, 다음 kernel이 다시 읽어 RoPE를 계산합니다. 그 결과도 저장한 뒤 Attention이 다시 읽습니다.

아래쪽은 세 연산을 하나의 fused kernel 안에서 이어 계산합니다. 중간값을 on-chip에서 바로 다음 연산에 사용하고, 마지막 결과를 global memory에 저장합니다. 계산할 내용은 같지만 중간값을 여러 번 내보냈다가 다시 읽는 비용을 줄이는 것입니다.

**화면 2/2 · Figure 10의 메모리 이동**

Figure 10에서는 메모리 이동을 화살표로 보여줍니다. 왼쪽은 세 kernel 각각에 global memory로 향하는 왕복 화살표가 있습니다. 오른쪽은 입력 $\mathbf{q},\mathbf{k},\mathbf{v}$를 읽고 최종 출력 $\mathbf{o}$를 저장하는 화살표만 남아 있습니다. 중간값을 저장하고 다시 읽던 이동이 줄어든 모습을 이렇게 확인할 수 있습니다.

## 29 · P109 · Evaluation and Analysis

이제 시뮬레이션과 실제 로봇에서 RLDX-1의 조작 성능을 확인하겠습니다.

## 30 · P040 · 시뮬레이션 벤치마크

먼저 시뮬레이션 평가입니다. 왼쪽 사진처럼 탁자 조작부터 양팔 로봇, 주방의 복합 작업까지 여러 환경에서 비교했습니다. LIBERO 계열과 SIMPLER는 기본 조작과 조건 변화 대응을, RoboCasa와 GR-1은 주방·양팔·복합 조작을 다룹니다. 각 benchmark의 데이터로 fine-tuning한 뒤의 조작 성공률을 보겠습니다.

## 31 · P022 · Simulation 결과 (a)

먼저 기본 조작과 환경 변화 대응을 보는 시뮬레이션 벤치마크의 결과입니다. RLDX-1이 비교한 모든 벤치마크에서 가장 높은 성공률을 기록한 것을 볼 수 있습니다.

가장 오른쪽 열은 각 벤치마크에서 기존 모델 중 성공률이 가장 높았던 값과 RLDX-1의 차이를 제가 추가한 것입니다.

LIBERO 계열에서는 기존 최고값과의 격차가 크지 않고, SIMPLER에서는5.4에서9.9%p 정도의 차이가 납니다. 차이의 크기는 평가마다 다르지만, 여러 벤치마크에서 고르게 비교 모델을 앞섰다는 점을 볼 수 있습니다.

## 32 · P095 · Simulation 결과 (b)

주방 조작과 GR-1 양팔 작업에서도 기존 최고값보다 각각4.4%p,10.7%p 높습니다. 다만 RoboCasa365의 복합 작업을 보면, 학습한 절차의 성공률은19.0%, 새로운 절차는5.6%입니다. 다른 모델보다 높은 결과를 얻었어도, 여러 동작을 끝까지 이어 수행하는 문제에는 여전히 어려움이 남아 있습니다. 이제 실제 로봇에서도 이런 경향이 나타나는지 보겠습니다.

## 33 · P023 · OpenArm · 지시와 새 조건

OpenArm에서는 지시에 맞춰 물체를 골라 옮기는 성능을 비교했습니다. 오른쪽 그래프의 회색이 π0.5와 GR00T N1.6이고, 초록색이 RLDX-1입니다. 선반에 놓기는 가장 높은 기존 모델54.2%에서68.8%로, 식기대에 놓기는58.3%에서70.8%로 높아졌습니다. 새 물체와 새 작업 조합에서도 두 모델보다 높은 결과를 얻었습니다. 언어 지시와 대상 변화에 대응하는 조작에서 전반적인 개선을 보인 것입니다.

## 34 · P024 · ALLEX · 움직임·기억·접촉

ALLEX는 움직이는 물체 잡기, 숨긴 물체 기억하기, 카드와 따르기 조작을 비교합니다. 컨베이어는 기존 모델의 최고값50.0%에서87.5%로, 숨긴 상자 선택은33.3%에서91.7%로 높아졌습니다. 카드와 따르기에서도 초록색 막대가 가장 높습니다. 이 두 과제는 부분 완료를 포함한 진행 점수이고, 오른쪽 평균86.8도 성공률과 진행 점수를 함께 평균한 값입니다. 이런 지표 구분을 유지하면서 보면, 시간 정보와 물리적 상호작용이 필요한 과제에서 큰 성능 차이가 나타났습니다.

## 35 · P025 · Franka · 성과와 남은 어려움

Franka에서도 모든 과제에서 두 비교 모델보다 높은 성공률을 얻었습니다. 회전 방향 판단은 기존 최고32.3%에서97.9%로, 숨긴 컵 선택은54.2%에서91.7%로 높아졌습니다. 전체 평균은 기존 모델34.4%,31.6%에 비해 RLDX-1이68.5%입니다. 다만 플러그 삽입의 절대 성공률은33.3%여서 정밀 조작에는 어려움이 남아 있습니다. 기존 모델 대비 개선과 아직 남은 한계를 함께 볼 수 있는 결과입니다.

## 37 · P060 · VLM 특징과 로봇 VQA

먼저 행동 모델에 전달할 VLM 특징을 어디에서 꺼낼지 비교했습니다. 왼쪽에서8층은51.1%,18층은60.9%,28층은56.3%로 중간18층이 가장 높습니다. 행동을 만들려면 대상이 어디에 있는지와 무엇을 해야 하는지를 함께 알아야 합니다. 저자들은 중간층이 이 시각 정보와 의미 정보를 함께 활용하기 좋은 균형점이라고 해석합니다.

오른쪽은 로봇 VQA의 효과입니다. 손과 물체의 관계, 작업과 행동을 추가 학습한 VLM을 쓰자, 정책의 조작 성공률이57.5%에서60.9%로 높아졌습니다. 특징을 꺼내는 위치도 중요하고, 그 특징을 로봇 조작에 맞춰 학습하는 것도 도움이 된다는 결과입니다.

## 38 · P062 · VQA 전후의 Attention

## 39 · P064 · 합성 데이터의 성능 효과

합성 데이터는 실제 데이터를 고정한 상태에서, 사용할 수 있는 합성 데이터의 양을 늘려 비교했습니다. 표의25%,50%,100%는 전체 합성 데이터 중 사용할 수 있는 범위입니다. 합성을 쓰는 조건에서는 실제와 합성을 뽑는 비율을 모두1대1로 유지했습니다. 합성 데이터를 쓰지 않을 때41.0%였던 성공률은 전체 합성 데이터를 사용했을 때50.1%로,9.1%p 높아졌습니다. 실제 시연을 더 다양한 합성 경험으로 보완한 효과입니다.

## 40 · P066 · RECAP · 전구 비틀기 개선

다음은 ALLEX가 전구를 비틀어 켜는 작업입니다. 시연으로 학습한 BC policy에서 출발해, 실제 실행 경험을 모으고 RECAP으로 다시 학습하는 과정을 세 번 반복했습니다. 오른쪽 그래프는 완료까지 걸린 프레임 수와 전구를 비튼 횟수로, 모두 낮을수록 좋습니다. BC에서 RECAP3로 가면서 완료 프레임 수는1056에서353으로, 비틀기 횟수는12.7에서4.1로 줄고 분포도 좁아졌습니다. 더 적은 시간과 동작으로, 더 일정하게 작업을 마치게 된 것입니다.

## 41 · P068 · 추론 최적화의 효과

마지막은 앞서 설명한 추론 최적화의 효과입니다. 같은 장비와 입력 조건에서 실행 방식을 바꿔 비교했습니다. 오른쪽 All-modality 열을 보면, 기본71.2ms에서 Graph와 Compile을 적용하면59.6ms, 한 graph로 묶는 Static Conversion까지 적용하면48.9ms, Kernel Optimization까지 더하면43.7ms입니다. 전체적으로 policy 추론 중앙값이 약38.6% 줄었습니다. 호출과 메모리 이동을 줄이는 최적화가 실제 지연 감소로 이어진 결과입니다.

## 42 · P111 · My opinions and limitation

마지막으로 복잡한 조작과 반복 생성의 계산 비용에 대한 제 의견을 말씀드리겠습니다.

## 43 · P028 · 나의 의견: 복잡한 조작

여기부터는 결과를 보고 제가 느낀 점입니다. RLDX-1은 움직임, 기억, 물리 센싱처럼 조작에 필요한 정보를 폭넓게 행동 생성에 연결했습니다. 그런데 이런 기능을 갖추는 것만으로 복잡한 작업이 안정적으로 해결되지는 않았습니다.

오른쪽을 보면 RoboCasa365의 복합 절차 성공률은 학습한 절차에서 19.0%, 새로운 절차에서 5.6%입니다. 실제 Franka에서도 컵 교체는 45.8%, 플러그 삽입은 33.3%입니다. 서로 다른 평가 조건이지만, 여러 행동을 순서대로 이어 가거나 정밀하게 맞춰야 하는 조작에 어려움이 남는다는 사례입니다.

모든 평가에서 세 모듈을 동시에 쓴 것은 아니므로, 이 숫자로 모듈 결합의 효과를 단정하지는 않겠습니다. 제가 보는 한계는 필요한 기능들을 잘 연결한 설계와 복잡한 작업을 끝까지 안정적으로 수행하는 능력 사이에 아직 간격이 있다는 점입니다.

## 44 · P030 · 나의 의견: 반복 생성의 비용

두 번째는 반복 생성에 드는 계산 비용입니다. Diffusion이나 여기서 사용한 flow matching처럼 후보를 여러 번 다듬는 정책은, 행동을 얻기까지 예측과 갱신을 반복합니다. 로봇이 계산하는 동안에도 물체와 주변 환경은 변하므로, 이 시간이 길면 새 상황에 반응하는 데 부담이 됩니다.

RLDX-1도 이런 부담을 줄이기 위해 실행 최적화를 적용했습니다. Table 4의 Euler 4회 설정에서는 policy 추론 중앙값이 71.2ms에서 43.7ms로 줄었습니다. 제 생각에는 반복 denoising 정책을 쓰는 로봇 기반 모델에서 이런 최적화가 선택적인 마무리가 아니라, 실제 반응 속도를 확보하기 위한 중요한 설계 요소입니다.

반복이 필요하다는 계산 구조의 제약을 말하는 것이고, 모든 RFM이 같은 구조라는 뜻은 아닙니다. 이 보고서에는 다른 종류의 정책과 같은 조건에서 속도를 비교한 결과가 없으므로, 언제나 더 느리다고 일반화하지는 않겠습니다. 생성 품질을 유지하면서 반복 계산과 전체 반응 지연을 어떻게 줄일지가 중요한 과제라고 생각합니다.
