## 01 · S001 · RLDX-1 Technical Report

오늘은 로봇 조작 모델인 RLDX-1 기술 보고서를 소개하겠습니다. 이 연구는 영상과 언어를 이해하는 능력에 더해, 실제 조작에 필요한 움직임 인식, 장기 기억, 물리 센싱을 어떻게 연결할지 다룹니다.

발표에서는 먼저 기존 VLA가 어떤 상황에서 어려움을 겪는지 보고, Figure 3을 중심으로 모델의 처리 과정을 따라가겠습니다. 그다음 데이터와 학습 방법, 추론 최적화를 살펴보고, 실제 실험에서 무엇이 개선됐는지 확인하겠습니다.

## 02 · P002 · 기존 VLA의 문제

VLA는 Vision-Language-Action의 약자입니다. 영상 관측과 언어 지시를 받아 로봇의 행동을 생성하는 모델입니다. 여러 물체와 작업을 이해하고 대응하는 범용성이 강점입니다.

그런데 실제 조작에서는 장면과 지시의 의미를 이해하는 것만으로 충분하지 않은 경우가 있습니다. 움직이는 물체를 잡으려면 어느 방향으로 움직이는지 알아야 하고, 물체를 상자에 숨겼다면 앞서 어느 상자에 넣었는지 기억해야 합니다. 접촉 부위가 가려졌거나 힘의 작은 차이가 중요할 때는 촉각과 토크 정보도 필요합니다.

화면의 세 상황이 이런 어려움을 보여주는 예시입니다. 저자들이 강조하는 것은 범용 지능에 더해 이러한 기능을 명시적으로 지원해야 한다는 점입니다. 여기서 functional capabilities는 움직임 인식, 장기 기억, 물리 센싱 같은 기능을 뜻합니다.

## 03 · P031 · RLDX-1 Overview

Figure 2는 이 연구의 전체 구성입니다. RLDX-1은 관측과 지시에서 조작에 필요한 특징을 뽑고, 이를 조건으로 미래 행동 묶음을 생성합니다. 행동 묶음인 action chunk는 앞으로 수행할 여러 시점의 행동을 한 번에 예측한 것입니다.

이때 움직임을 읽는 모듈, 과거 정보를 활용하는 memory, 사용 가능한 촉각·토크 입력을 연결합니다. 이 구조를 학습시키기 위해 공개 시연·자체 시연·합성 데이터를 사용하고 세 단계 학습을 수행합니다. 실행할 때의 지연을 줄이는 최적화까지 포함해 뒤에서 차례로 보겠습니다.

지금은 구조·데이터·학습·실행이라는 큰 흐름을 잡고, 다음 Figure 3에서 관측이 행동으로 바뀌는 경로를 살펴보겠습니다.

## 04 · P032 · RLDX-1 Architecture

> 조작: 페이지 번호 4로 진입하면 1/27의 전체 그림에서 시작한다. 아래에서 지정한 화살표는 슬라이드 내부의 설명 화살표다. 오른쪽 방향키는 한 단계씩 진행한다.

### 단계 01/27 · 전체 구조

왼쪽은 영상과 언어에서 특징을 만드는 VLM이고, 오른쪽은 행동을 생성하는 MSAT입니다. 아래 Memory Module은 이전에 계산한 특징을 보관하고 읽습니다. 영상이 들어와서 어떤 정보를 거친 뒤 행동이 되는지, 왼쪽부터 따라가겠습니다.

### 단계 02/27 · Vision Encoder 확대

먼저 Vision Encoder입니다. 한 장의 사진만 보는 것이 아니라 여러 시점의 관측을 함께 받습니다. 실제 pre-training에서는 현재를 기준으로 −6, −4, −2, 0의 네 시점 관측을 사용합니다. 이를 통해 물체의 현재 모습과 앞서 어떻게 움직였는지를 함께 볼 수 있습니다.

### 단계 03/27 · 첫 화살표: 1–9층

Vision Encoder는 총 27개 ViT 층으로 구성됩니다. 먼저 1–9층이 영상의 시각 특징을 추출하고, 9층 뒤에 움직임 정보를 명시적으로 추출하는 Motion Module을 넣습니다. 약 30% 깊이에서 물리적 단서가 풍부하다는 선행 관찰을 참고한 위치입니다.

### 단계 04/27 · 두 번째 화살표: Motion Extractor

Motion Extractor에서는 STSS, 시공간 자기 유사성을 계산합니다. 각 특징과 주변 위치·인접 시점 특징의 상관을 구하고, 그 결과를 encoder로 처리해 움직임 특징을 만듭니다.

직관적으로 공이 지금 같은 위치에 있더라도, 이전에 왼쪽에 있었는지 오른쪽에 있었는지에 따라 이동 방향이 다르겠죠. 프레임 사이에 비슷한 특징이 어디에 나타나는지를 움직임의 단서로 활용하는 것입니다.

### 단계 05/27 · 세 번째 화살표: Residual addition

추출한 움직임 특징을 기존 시각 특징에 더합니다. 이것이 residual update입니다. 기존 시각 표현을 바탕으로 움직임 정보를 보정해서 넣는다고 이해하면 됩니다. 여기의 덧셈은 같은 위치와 차원을 맞춘 원소별 덧셈이므로 특징의 shape는 유지됩니다.

### 단계 06/27 · 네 번째 화살표: 10–27층

움직임 정보가 더해진 특징은 나머지 10–27층에서 계속 처리합니다. 이렇게 얻은 영상 특징 토큰이 다음 VLM으로 넘어갑니다. 여러 프레임 입력은 pre-training부터 사용하고, 이 STSS 모듈은 뒤의 mid-training에서 추가한다는 점도 기억해 두겠습니다.

### 단계 07/27 · 전체 그림으로 복귀

지금까지는 영상에서 움직임을 반영한 시각 특징을 만드는 과정이었습니다. 이제 이 특징이 언어 지시와 함께 처리되는 VLM 부분을 보겠습니다.

### 단계 08/27 · VLM 확대

VLM은 영상의 내용과 언어 지시를 함께 이해합니다. 여기서는 Qwen3-VL 8B를 로봇 관련 VQA로 추가 학습한 RLDX-1-VLM을 사용합니다. VQA를 왜 하는지는 다음 장에서 설명하고, 지금은 특징이 만들어지는 경로를 따라가겠습니다.

### 단계 09/27 · 첫 화살표: 세 종류의 입력 토큰

보라색은 영상 토큰, 연한 초록색은 언어 토큰, 청록색은 cognition tokens입니다. 세 묶음을 이어 붙여 VLM에 넣습니다. Cognition tokens는 64개의 학습 가능한 query token입니다.

처음부터 완성된 인지 정보가 들어 있는 것은 아닙니다. Transformer의 attention을 거치면서 영상과 언어를 참고하고, 행동 예측에 필요한 정보를 모으는 위치로 학습됩니다.

### 단계 10/27 · 두 번째 화살표: 초반 1–4층

초반 층에서는 여러 시점의 관측을 시간순으로 처리합니다. Causal attention으로 앞선 시점이 뒤의 정보를 미리 읽지 않도록 하고, 뒤쪽의 현재 관측과 cognition 위치가 앞선 정보를 참고하면서 시간 맥락을 모읍니다.

여기의 4층은 한 번의 VLM 계산 안에서 거치는 Transformer 층입니다. 로봇 시간이 네 번 흐른다는 의미는 아닙니다.

### 단계 11/27 · 세 번째 화살표: 과거 프레임 압축

4층 뒤에서는 과거 관측 위치의 hidden states를 평균 풀링해 context token 하나로 압축합니다. 현재 관측, 언어 지시, cognition tokens는 유지합니다. 이후 층에서 처리할 토큰 수를 줄이기 위한 설계입니다.

Qwen3-VL의 DeepStack은 여러 수준의 시각 특징을 첫 네 LLM 층에 주입합니다. 저자들은 이 과정을 먼저 활용한 다음 과거 관측을 압축하도록 구성했습니다.

### 단계 12/27 · 네 번째 화살표: Cognition features

중간층에서 cognition token 위치에 해당하는 출력 특징만 가져옵니다. 이것이 $\mathbf h_t$입니다. 입력 토큰을 붙였다고 바로 $\mathbf h_t$가 되는 것이 아니라, 영상과 언어를 참고해 갱신된 해당 위치의 hidden vectors를 선택하는 것입니다.

64개 cognition 위치의 특징을 행동 모델에 전달합니다. 다른 위치의 출력도 내부 계산에는 기여했지만, 행동 모델로 넘기는 출력은 이 cognition features로 정리합니다. 왜 중간층을 택했는지는 뒤의 ablation에서 확인하겠습니다.

### 단계 13/27 · 전체 그림으로 복귀

이제 현재 관측과 지시에서 $\mathbf h_t$가 만들어졌습니다. 하지만 짧은 관측 구간보다 더 이전에 일어난 사건이 필요할 수 있습니다. 그 역할을 Memory Module이 맡습니다.

### 단계 14/27 · Memory Module 확대

예를 들어 물체를 어느 상자에 넣었는지 본 뒤 상자가 가려지면, 현재 영상만으로는 선택할 수 없습니다. 그래서 이전에 계산한 cognition features를 저장해 두고 현재 특징과 함께 읽습니다. 과거 영상 전체를 매번 다시 처리하는 대신 특징을 활용하는 방식입니다.

### 단계 15/27 · 첫 화살표: 과거 특징 Queue

아래 줄의 $\mathbf Q_t$가 과거 cognition features를 보관하는 queue입니다. 논문의 설정에서는 과거 세 시점의 특징 묶음을 사용합니다. 한 시점에 64개이므로 과거 부분에는 3×64, 총 192개의 특징 벡터가 있습니다.

### 단계 16/27 · 두 번째 화살표: 현재 특징 연결

과거 queue에 현재 $\mathbf h_t$를 토큰 방향으로 이어 붙여 Memory Transformer에 넣습니다. 과거 세 묶음과 현재 한 묶음이 함께 들어가는 것입니다. 이때는 concat이므로 토큰의 개수가 늘어납니다.

### 단계 17/27 · 세 번째 화살표: Causal Transformer

Memory Transformer도 causal attention으로 시간 순서를 유지합니다. 뒤쪽 시점은 자기 자신과 앞선 이력을 읽고, 이를 통해 memory features인 $\mathbf m_t$를 만듭니다. 현재 판단에 과거 사건의 정보를 반영하는 과정입니다.

### 단계 18/27 · 네 번째 화살표: $\mathbf h_t$와 $\mathbf m_t$ 연결

현재 특징 $\mathbf h_t$와 memory 특징 $\mathbf m_t$를 이어 붙여 행동 모델의 C stream으로 전달합니다. 본문의 [$\mathbf h_t$, $\mathbf m_t$] 표기에 따라 토큰 방향의 concat으로 이해하겠습니다.

과거 특징을 매 프레임 전부 저장하지는 않습니다. Mid-training의 명시 설정에서는 ALLEX가 40 timestep 간격의 과거 세 묶음, Franka가 16 timestep 간격의 과거 세 묶음을 사용합니다. 정확한 queue 갱신·초기화 규칙에는 남은 질문이 있어 마지막에 짚겠습니다.

### 단계 19/27 · 전체 그림으로 복귀

여기까지가 행동 생성에 사용할 인지·기억 특징을 만드는 경로입니다. 이제 이 특징과 현재 로봇 상태, 물리 센서 정보를 함께 읽는 MSAT를 보겠습니다.

### 단계 20/27 · MSAT 확대

MSAT는 Multi-Stream Action Transformer입니다. 성격이 다른 정보를 각각의 stream에서 처리하면서 joint self-attention으로 정보를 교환합니다. 지금 그림은 물리 신호가 있는 경우여서 P·C·A의 세 stream을 보여줍니다.

### 단계 21/27 · 첫 화살표: P stream

P는 physics stream입니다. 현재 측정한 촉각·토크 신호와, 앞으로의 물리 신호를 예측하기 위한 noisy 미래 후보가 들어갑니다. 접촉 부위가 가려지거나 힘의 차이가 중요한 작업에서 이런 신호를 활용합니다. 센서가 없는 경우에는 P stream의 attention을 mask할 수 있습니다.

### 단계 22/27 · 두 번째 화살표: C stream

C stream에는 앞에서 만든 현재 cognition features와 memory features가 들어갑니다. 무엇을 보고 있고 어떤 지시를 받았는지, 과거에 어떤 일이 있었는지를 행동 생성의 조건으로 제공하는 부분입니다.

### 단계 23/27 · 세 번째 화살표: A stream

A stream에는 현재 로봇 상태와 noisy action chunk가 들어갑니다. 현재 상태는 로봇이 지금 어떤 자세인지 알려주고, noisy action chunk는 모델이 다듬어 갈 미래 행동 후보입니다. 후보를 어떻게 만들고 갱신하는지는 뒤의 수식 장에서 설명하겠습니다.

### 단계 24/27 · 네 번째 화살표: Triple-stream blocks

초반에는 P·C·A가 각각의 normalization과 projection을 사용합니다. Attention에서는 서로의 정보를 참고하고, 출력은 다시 원래 stream으로 나누어 residual로 갱신합니다. 전용 경로를 둔다는 것은 파라미터를 구분한다는 뜻이고, 정보 교환은 joint attention이 담당합니다.

### 단계 25/27 · 다섯 번째 화살표: Double-stream blocks

뒤쪽에서는 C와 A의 토큰 시퀀스를 합쳐 한 경로로 처리합니다. P 경로는 별도로 유지하면서 합쳐진 C-A와 정보를 교환합니다. 초반 attention 결과를 나누어 갱신하는 것과, 이 뒤쪽 단계에서 C와 A를 통합하는 것은 구분해야 합니다.

### 단계 26/27 · 여섯 번째 화살표: 변화율과 반복 갱신

한 번의 forward에서 얻는 것은 미래 후보를 어느 방향으로 얼마나 바꿀지 나타내는 변화율입니다. 그 값으로 후보를 갱신하고, 같은 조건을 참조하면서 다시 MSAT를 통과시킵니다. 각 denoising 단계에서 Triple-stream과 Double-stream blocks를 모두 거칩니다.

이 반복이 끝나면 최종 미래 행동과 물리 신호를 얻습니다. 조건인 $\mathbf h_t$, $\mathbf m_t$, 현재 상태와 센서는 유지하고, noisy 미래 후보가 갱신되는 과정입니다.

> 조작: 이 화면을 유지한 채 아래 입출력 경로 설명까지 말한다. 별도의 페이지나 추가 화살표는 없다.

마지막으로 로봇마다 관절 수와 제어 형식이 다른데 어떻게 같은 MSAT를 사용할 수 있는지 보겠습니다. 로봇별로 얇은 input·output projection을 둡니다. 입력을 공유 특징 공간으로 바꾸고, 모델이 예측한 변화율을 해당 로봇의 행동 공간으로 되돌리는 연결층입니다.

새 로봇 적응의 출발점을 준비하기 위해, 로봇 구분 없이 쓰는 공통 encoder–decoder도 함께 학습합니다. 입력 크기를 padding으로 맞춰 여러 로봇의 데이터를 공통 경로에 연결합니다. 로봇별 입출력 규격을 다루는 projection과 물리 센서를 다루는 P stream은 역할이 다릅니다.

### 단계 27/27 · 전체 경로 정리와 다음 장 연결

전체 경로를 다시 보면, 영상과 언어에서 cognition을 만들고, 과거 특징에서 memory를 얻은 뒤, 로봇 상태·물리 신호와 함께 행동 후보를 반복 갱신합니다. 이제 각 부분을 조금 더 구체화하겠습니다. 먼저 VLM을 로봇 조작에 맞추는 VQA 학습을 보겠습니다.

> 발표자 참고: STSS를 정확한 속도나 optical flow의 직접 출력이라고 설명하지 않는다. Memory의 H/H+1 간격 표기와 cache 갱신·초기화는 미해결이다. 그림의 연결 기호는 덮어쓰지 않고 본문의 concat 설명을 따른다. 공통 경로의 학습은 매 batch에서256 trajectories를 보내는 설정이며, 전체 데이터 수가256개라는 뜻이 아니다. 질문이 있을 때 보충한다.

## 05 · P051 · VLM과 로봇 VQA

범용 VLM이 장면을 잘 설명한다고 해서, 그 이해가 바로 로봇의 제어와 연결되는 것은 아닙니다. 저자들은 하위 작업 추론, 공간 관계 이해, low-level 행동으로의 grounding이 부족할 수 있다고 지적합니다.

이를 보완하려고 로봇 관측에서 질문과 답을 만들어 VQA 학습을 합니다. 첫째는 손끝과 목표 물체의 공간 관계, 둘째는 목표를 이루기 위한 중간 subtask, 셋째는 현재 프레임에 대응하는 low-level action입니다. 직관적으로는 손이 물체에 비해 어디에 있고, 지금 어느 단계를 해야 하며, 어떤 제어가 대응되는지를 배우는 것입니다.

이렇게 Qwen3-VL 8B를 추가 학습한 결과가 RLDX-1-VLM입니다. Figure 3에는 학습 결과인 이 VLM의 처리 경로가 표시되어 있고, VQA 학습 블록은 따로 없습니다. VQA는 이 VLM을 준비하는 학습 과정으로 구분해 보시면 됩니다. 실제 행동 chunk는 뒤의 Action Model이 생성합니다. 조작 성능에 도움이 됐는지는 ablation에서 확인하겠습니다.

## 06 · P009 · MSAT의 입력

앞서 그림에서 본 입력을 기호로 정리한 장입니다. C에는 현재 cognition $\mathbf h_t$와 memory $\mathbf m_t$가 들어갑니다. A에는 denoising timestep을 알리는 토큰, 현재 로봇 상태, noisy action chunk가 들어갑니다. P에는 현재 센서와 noisy 미래 센서 chunk가 들어갑니다.

여기서 두 종류의 시간을 구분하겠습니다. t부터 t+H는 로봇이 앞으로 수행할 행동의 시간 순서이고, τ는 후보를 다듬는 denoising timestep입니다. τ는 sin·cos embedding과 MLP를 거쳐 A 앞의 한 토큰으로 들어갑니다. Joint attention을 통해 다른 stream도 그 정보를 참고할 수 있습니다.

행동 chunk 안의 시간 순서는 RoPE로 반영합니다. Query와 key를 위치에 따라 회전시켜 attention 계산에 상대 위치가 반영되도록 하는 방법입니다. 이 정보들을 받은 뒤 stream 사이의 실제 계산이 어떻게 이루어지는지 보겠습니다.

## 07 · P010 · MSAT의 Joint Attention

각 stream은 자신의 RMSNorm과 QKV projection으로 입력을 변환합니다. RMSNorm은 특징의 크기를 정규화하고, projection은 attention 계산에 사용할 query·key·value를 만드는 변환입니다. 이렇게 만든 Q끼리, K끼리, V끼리를 토큰 방향으로 이어 붙여 joint self-attention을 수행합니다.

설명용으로 C가 네 토큰, A가 세 토큰이라고 하겠습니다. Attention의 출력도 일곱 위치에 대응하므로 앞의 네 개는 C, 뒤의 세 개는 A로 돌려보낼 수 있습니다. 서로의 정보를 참고했어도 출력이 어느 query 위치에 대응하는지는 남아 있기 때문입니다.

그 결과를 각 stream의 원래 특징에 더해 residual update를 합니다. 이후 SwiGLU FFN은 gate를 이용해 각 토큰 내부의 특징을 비선형으로 바꿉니다. 여기까지가 정보를 교환하는 구조였고, 다음은 이 신경망이 무엇을 정답으로 배우는지입니다.

## 08 · P006 · Action Model의 학습 원리

왼쪽의 $\mathbf a$는 시연에서 얻은 정답 action chunk이고, 위에 τ가 붙은 $\mathbf a^\tau$는 denoising timestep τ에서의 noisy action chunk입니다. 이 둘을 구분해야 합니다.

$$
\mathbf a^\tau=\tau\mathbf a+(1-\tau)\boldsymbol\epsilon
$$

학습할 때 정답과 같은 shape의 표준 정규 노이즈를 뽑고, 이 식으로 noisy 입력을 만듭니다. τ가0이면 완전 노이즈이고,1이면 정답 action chunk가 됩니다. 노이즈에서 정답을 잇는 직선 경로를 만들어 둔 것입니다.

이 식을 τ로 미분하면 a−epsilon이 나옵니다. 만들어 둔 경로의 정확한 변화율을 계산할 수 있으므로 이것을 정답 변화율 $\mathbf v^*$로 씁니다. 시연과 노이즈 쌍이 달라지면 이 정답도 달라집니다. 오른쪽 $\mathbf u_\theta$는 MSAT로 구현한 학습 가능한 neural vector field이고, 이 함수를 현재 입력에서 계산한 결과가 예측 변화율입니다.

손실은 예측 변화율과 정답 변화율의 차이를 L2 norm의 제곱으로 계산합니다. Chunk 전체 좌표에서 오차를 제곱해 더하는 것으로 이해하면 됩니다. 조건 $\mathbf c_t$에는 인지, 기억, 현재 상태와 사용 가능한 센서 정보가 들어갑니다. 이 오차를 줄이도록 모델을 학습한 뒤, 추론에서 변화율을 어떻게 사용할지 보겠습니다.

용어를 정리하면 Transformer는 신경망의 구조이고, flow matching은 이 변화율을 학습시키는 목표입니다. 다음 장의 Euler 방법은 학습한 변화율로 실제 행동 후보를 갱신하는 방법입니다.

## 09 · P008 · Action Model의 추론 수식

추론에서는 정답 행동을 알 수 없으므로 랜덤 노이즈에서 시작합니다. 현재 후보와 denoising timestep, 조건을 모델에 넣으면 chunk 전체의 변화율을 예측합니다.

$$
\mathbf a^{\tau_{i+1}}=\mathbf a^{\tau_i}+
(\tau_{i+1}-\tau_i)\mathbf u_\theta(\mathbf a^{\tau_i},\tau_i,\mathbf c_t)
$$

이 식은 현재 후보에 이번 이동량을 더한다는 뜻입니다. 모델의 출력은 변화율이므로 denoising timestep 간격을 곱해 갱신량으로 바꿉니다. 그 후보에서 다시 변화율을 구하고 갱신하는 Euler 방법입니다. 추론 중에는 학습된 가중치를 고정한 채 후보를 바꿉니다.

물리 센서를 사용하는 경우에는 미래 센서 후보도 같은 방식으로 함께 갱신합니다. 현재 센서는 관측된 조건이고 미래 센서는 예측 대상입니다. 한 번의 행동 생성 안에서는 조건을 유지하며 반복하고, 이 과정이 끝난 뒤에 행동을 실행합니다.

## 10 · P071 · Action Chunk의 실행

한 번에 예측한 행동을 모두 끝까지 실행할 필요는 없습니다. 이 보고서의 RL 설정에서는40개의 행동을 예측하지만 앞의20개만 실행한 뒤 새 관측으로 다시 정책을 호출합니다.

여기에는 두 반복이 있습니다. 안쪽 반복은 현재 관측을 고정하고 denoising해 행동 chunk를 만드는 과정입니다. 바깥쪽 반복은 일부 행동을 실행하고 새로 관측해 다음 chunk를 만드는 과정입니다. 환경의 변화를 반영할 기회를 계속 주는 것입니다.

이40개 생성·20개 실행은 해당 RL 설정이고, 다른 벤치마크의 실행 길이까지 동일하다는 뜻은 아닙니다. 이제 이러한 모델을 학습시키는 데이터가 어디서 오는지 살펴보겠습니다.

## 11 · P013 · 학습 데이터

학습 데이터는 세 가지 역할로 정리할 수 있습니다. 공개 실제 데이터는 다른 로봇들이 이미 해본 경험이고, 자체 실제 데이터는 목표 로봇으로 직접 모은 경험입니다. 합성 데이터는 기존 시연을 바탕으로 새로운 장면과 동작의 영상을 만들어 경험 범위를 넓힙니다.

공개 데이터에서는 조작의 기본기를, 자체 데이터에서는 목표 로봇의 제어와 센서 활용을 배웁니다. 합성 데이터는 직접 수집하기 어려운 다양한 상황을 보완합니다.

왼쪽 Figure 4는 특히 합성 데이터의 흐름입니다. 영상을 생성하는 것에서 끝나지 않고 행동 라벨을 붙이고 검증해야 합니다. 먼저 공개·자체 데이터부터 보고 이 흐름으로 돌아오겠습니다.

## 12 · P033 · 공개 실제 데이터

공개 데이터는 실제 로봇이 무엇을 보고 어떻게 움직였는지를 연결해 둔 시연 기록입니다. 한 번의 시연에서 관측과 행동이 시간순으로 이어진 기록을 trajectory라고 부릅니다.

OXE는 여러 기관과 로봇의 데이터를 모은 묶음이고, DROID는 Franka의 다양한 현장 조작입니다. Galaxea, AgiBot, ActionNet, Everyday는 양팔 로봇과 휴머노이드의 여러 작업을 제공합니다. 여기서는 이름을 모두 외우기보다 서로 다른 몸체와 작업의 경험을 모은다는 점이 중요합니다.

컵을 잡고 옮기는 것처럼 여러 작업에서 반복되는 조작 패턴을 배웁니다. 보고서의 action prior는 이러한 조작의 기본기로 이해할 수 있습니다. 그다음 목표 로봇에서만 얻을 수 있는 경험을 추가합니다.

## 13 · P034 · 자체 실제 데이터

자체 데이터는 목표 로봇 특화와 새 기능 학습을 위해 수집합니다. 특히 영상과 행동만이 아니라 물리 센서 정보까지 함께 기록한다는 점이 중요합니다.

Franka에서는 원격 조작으로 시연을 모으며 AnySkin 촉각과 관절 토크를 함께 기록합니다. ALLEX에서는 팔과 손, 머리와 허리를 부위별로 원격 조작하고 모터 전류에서 관절 토크를 추정합니다. 사람의 시연이 로봇의 수치 행동과 센서 기록으로 연결되는 것입니다.

이 데이터는 목표 로봇의 제어와 기억·물리 센싱 같은 새 입력을 학습하는 지도 신호를 제공합니다. 따라서 자체 데이터를 수집하는 목적에는 물리 센싱 학습도 포함됩니다. 공개 데이터만으로 부족한 목표 로봇의 경험을 채우는 역할입니다.

## 14 · P072 · 로봇 영상 생성 모델

합성 데이터를 만들기 전에 영상 생성 모델부터 로봇 시연에 맞게 추가 학습합니다. 일반적인 영상 생성 능력만으로는 로봇의 시점과 조작 동작을 충분히 표현하기 어렵기 때문입니다.

시연 영상으로 로봇의 모습과 동작을 학습한 생성 모델을 준비하고, 그 모델에 지시와 시작 장면을 주어 합성 영상을 만듭니다. 여기의 생성 모델과 행동을 실행하는 RLDX-1은 별도의 모델입니다. 하나는 학습 재료인 영상을 만들고, 다른 하나는 그 데이터를 활용해 로봇 행동을 배웁니다.

## 15 · P014 · Task·Scene Augmentation

Figure 5에서 원본, task 변형, scene 변형을 차례로 보겠습니다. Task augmentation은 할 일을 바꾸고, scene augmentation은 장면의 외관을 바꿉니다.

지시를 만드는 첫 방법은 행동·대상 물체·놓을 위치·손 종류를 나누어 재조합하는 것입니다. 둘째는 원래 지시의 pick, pour, push 같은 기본 skill을 먼저 추출해 조건으로 쓰는 방법입니다. 원래 행동을 유지하며 대상이나 위치를 바꾸거나, 미리 정한 집합의 다른 실행 가능한 skill로 바꿀 수 있습니다. 두 방법의 결과는 겹칠 수 있지만 지시 생성의 조건을 구성하는 방식이 다릅니다.

장면 쪽에서는 시작 이미지를 I2I로 편집하고, 그 이미지에서 I2V로 영상을 생성합니다. 컵이나 손, 테이블의 윤곽을 나타내는 Canny edge map을 조건으로 주어 대략적인 배치와 형태를 따라가도록 유도합니다. 윤곽선 안내선을 참고하면서 외관을 바꾸는 것으로 생각하면 됩니다. Figure 5(c)가 이 경로의 예입니다.

영상 수준의 V2V에서는 움직임과 물체의 정체·형태를 유지하면서 색과 질감을 다양화하려고 합니다. 이미지 편집과 영상 변형은 허용하는 변화 범위가 다릅니다. 이렇게 만든 영상이 그럴듯하고 행동 라벨과도 맞는지 다음 단계에서 확인합니다.

> 발표자 참고: 실행 가능한 지시를 만들려는 설계와 실제 실행 가능성을 보장하는 것은 구별한다. 구체적인 skill 목록·prompt·판정 규칙은 미해결 질문에 남긴다. Canny 조건도 위치·접촉·물리 타당성을 보장하는 규칙으로 설명하지 않는다.

## 16 · P015 · 합성 데이터 검증

검증은 두 질문으로 나누어 보겠습니다. 첫째, 영상의 동작이 지시와 맞고 그럴듯한가? 둘째, 영상에 붙인 수치 행동 라벨이 실제로 그 움직임을 설명하는가?

영상 자체는 검사용 VLM으로 지시 일치와 동작의 그럴듯함을 평가합니다. 원래 지시와 다른 동작이 만들어졌다면 관찰된 동작에 맞게 설명을 다시 붙이는 re-caption도 합니다. 접근 거리나 물체 상호작용이 그럴듯한지도 평가해 선별합니다.

그다음 그림의 A가 합성 영상입니다. 합성 영상에는 정답 로봇 제어값이 자동으로 주어지지 않으므로, 현재·미래 관측 쌍을 IDM에 넣어 그 사이의 수치 행동을 추정합니다. 이 행동이 pseudo-action label입니다. Task라는 언어 지시와 action이라는 수치 행동을 구분해야 합니다.

이 추정 행동을 시뮬레이터에서 실행하고 렌더링한 것이 B rollout 영상입니다. 따라서 비교하는 두 영상은 원래 합성 영상 A와, 그 영상에서 추정한 행동을 실행해 얻은 B입니다. 두 움직임이 맞는지를 검사해 영상·행동 쌍을 남깁니다.

구체적으로는 두 영상을 같은 frozen V-JEPA2 encoder로 처리해 특징을 얻습니다. 특징을 concat하고, 학습 가능한 query가 cross-attention으로 읽은 뒤 작은 head가 일치 여부를 판단합니다. Concat은 비교할 정보를 함께 배치하는 것이고, cross-attention은 별도의 query가 그 정보를 읽는 과정입니다. 이 판정기를 어떻게 학습하는지는 다음 장에서 보겠습니다.

> 발표자 참고: 영상 생성 모델, IDM, 영상 품질을 보는 VLM, 움직임 일치 판정기, RLDX-1 policy의 역할을 섞지 않는다. IDM은 SigLIP-2와0.1B DiT를 사용하며 flow matching으로 학습한다. 영상 품질 검사에는 Gemini API를 사용하고 지시 일치는16프레임, plausibility는8프레임을 입력한다. 세부 설정 질문이 있을 때 보충한다. 필터 통과를 현실 작업의 성공 보장으로 확대하지 않는다.

## 17 · P047 · 일치 검사기의 학습

판정기를 학습할 때는 실제 시연과 정답 행동을 기준으로 삼습니다. 실제 시연 영상과 그 시연의 정답 행동을 시뮬레이터에서 실행한 rollout을 짝지으면, 겉모습은 달라도 움직임이 대응하는 positive pair가 됩니다.

Negative pair는 같은 episode에서 시간 구간을 어긋나게 짝짓거나, 같은 task instruction을 가진 다른 episode의 영상을 짝지어 만듭니다. 같은 작업 이름이어도 손과 물체가 움직이는 구체적인 시점과 방식은 다를 수 있기 때문입니다.

고정한 영상 encoder 위에 작은 attentive probe를 학습합니다. 실제 시연·정답 행동으로 판정 기준을 배운 뒤, 앞 장의 합성 영상·IDM 추정 행동 쌍을 선별하는 데 사용합니다. 합성 쌍을 처음부터 정답 positive로 간주하는 과정은 아닙니다.

## 18 · P035 · 학습 단계

학습 목적은 세 단계로 구체화됩니다. Pre-training에서는 여러 로봇의 경험으로 범용 조작 정책을 배웁니다. Mid-training에서는 목표 로봇의 몸체와 센서에 맞추고 움직임·기억·물리 센싱 기능을 확장합니다. Post-training에서는 실제 목표 작업에 적응합니다.

직관적으로 기본기, 이 로봇의 몸과 감각, 이 작업의 수행 순서입니다. 다만 모든 실험이 세 단계와 RL을 모두 필수로 거친다는 뜻은 아닙니다. 특히 post-training의 기본은 모방학습이고 RL은 까다로운 작업에 추가하는 보완입니다.

이 구분을 기준으로 각 단계에서 어떤 데이터를 쓰고 무엇을 배우는지 보겠습니다.

## 19 · P016 · Pre-training

Pre-training은 새 로봇과 작업에 적응할 출발점이 될 범용 정책을 배우는 단계입니다. 여러 몸체와 작업을 포함한 약150만 episode의 데이터 pool을 사용합니다. 이때 pool은 준비해 둔 데이터 모음입니다.

Figure 6의 원 그래프는 학습 중 데이터를 뽑는 비중이고, 표의 episode 수는 보유 데이터의 크기입니다. 예를 들어 OXE는870K, DROID는92K로 보유량이 다르지만 학습 sampling 비중은 둘 다25%입니다. 단순히 데이터가 많은 만큼 더 자주 뽑는 방식은 아닙니다.

여러 실제 데이터와 함께 합성 GR-1 데이터도 포함해 조작 경험을 보완합니다. 여러 프레임 관측을 입력받고, 앞에서 본 flow-matching 목표로 행동 변화율을 학습합니다. 여기서 얻은 기본 정책을 다음 단계에서 목표 로봇에 맞춥니다.

> 발표자 참고: 공통 encoder–decoder에는 매 batch에서 무작위256 trajectories를 보낸다. 전용 경로를 없앤다는 뜻은 아니며 구체적인 이중 학습 순서를 임의로 설명하지 않는다. 전체 데이터의256개만 사용한다는 뜻도 아니다.

## 20 · P017 · Mid-training

여러 로봇의 기본 동작을 배웠더라도 ALLEX와 Franka의 몸체, 손, 센서를 잘 쓰려면 추가 적응이 필요합니다. Mid-training은 목표 로봇 특화와 새 기능 확장을 함께 수행합니다.

STSS Motion Module을 추가하고, 과거 cognition 세 묶음을 읽는 memory와 물리 신호 입력을 학습합니다. ALLEX에서는 토크, Franka에서는 토크와 촉각을 활용합니다. 이러한 새 기능의 지도 신호는 자체 시연 데이터가 제공합니다. 큰 데이터 공급원도 함께 섞어 기존의 폭넓은 조작 경험을 유지하려고 합니다.

처음2K alignment steps에서는 기존 파라미터를 고정하고 새 파라미터만 학습한 뒤 함께 학습합니다. 새 연결부를 기존 표현에 먼저 맞춘다고 이해할 수 있습니다. Physics 쪽의 near-zero 초기화도 새 경로가 처음부터 기존 출력을 크게 흔들지 않도록 시작하는 설계로 볼 수 있습니다.

화면의 혼합은 ALLEX 실제:합성5:5, Franka DROID:자체8:2입니다. 이 비율의 선택과 warmup·초기화 각각의 효과를 독립적으로 검증한 결과까지 제시한 것은 아닙니다.

## 21 · P018 · Post-training

Post-training에서는 목표 작업의 시연으로 모방학습을 합니다. 논문의 대부분 실험이 이 방식을 사용합니다. 먼저 작업별 시연을 모아 학습하고 실제로 실행해 본 뒤, 실패하는 조건에 시연을 추가해 재학습합니다.

예를 들어 물체가 새로운 위치에 놓이면 실패한다면 그 위치 범위를 더 포함하도록 시연을 수집합니다. 이때는 사람이 실패 조건의 좋은 동작을 추가로 보여 주는 것입니다.

그런데 휴머노이드의 큰 행동 공간이나 정밀한 접촉이 필요한 작업에서는 좋은 시연을 충분히 모으기 어렵습니다. 이런 어려운 조작을 더 개선하기 위해 RECAP 기반 RL refinement를 선택적으로 추가합니다. 논문은 특정 성공률 아래에서 자동으로 RL로 전환한다는 규칙을 제시하지는 않습니다. 다음은 이 RL 개선의 구성입니다.

## 22 · P019 · RECAP

RECAP에서는 행동을 만드는 policy와 상황을 평가하는 critic을 분리해서 학습합니다. Policy는 앞서 본 RLDX-1이고, critic은 별도의 Gemma3-4b-it VLM입니다. RLDX-1의 Qwen VLM을 그대로 공유하는 critic으로 보면 안 됩니다.

이 연구의 critic은 value를 숫자 텍스트로 예측합니다. 기존 VLM critic들이 새 value 예측 head를 붙여 학습하는 방식과 달리, 기존 VLM의 숫자 토큰·텍스트 출력 인터페이스를 활용합니다. 저자들은 기존 지식을 활용해 적은 데이터로 목표 작업에 적응하려는 설계라고 설명합니다.

절차는 먼저 시연 데이터로 critic을 학습하고, 그 평가에서 advantage labels를 만들어 policy를 학습하는 것입니다. 이후 현재 policy로 실제 rollout을 수집해 데이터를 합칩니다. 누적 데이터 중 성공 trajectory로 critic을 갱신하고, 전체 데이터에 labels를 다시 붙여 policy를 재학습합니다.

Advantage는 행동이 기대에 비해 얼마나 유리했는지에 대한 학습 신호로 이해하면 됩니다. 정확한 label 계산식은 보고서에 충분히 적혀 있지 않으므로 임의의 수식으로 확정하지 않겠습니다. 핵심은 critic이 로봇에 행동 명령을 직접 내리는 것이 아니라 policy를 개선할 학습 신호를 제공한다는 점입니다.

## 23 · P037 · Critic과 Figure 8

Figure 8은 두 critic이 작업 진행을 어떻게 평가하는지 보여줍니다. 파랑은 새 head로 value 분포를 예측하는 distributional critic이고, 초록은 기존 텍스트 출력으로 숫자 value를 예측하는 제안 방식입니다. 여기의 비교를 모든 종류의 일반 critic에 대한 구분으로 확대하지는 않겠습니다.

가로축은 실제 로봇 timestep, 세로축은 정규화한 value입니다. 왼쪽은 첫 시도에 성공한 사례입니다. 초록 곡선이 작업이 진행될수록 비교적 꾸준히 올라갑니다. 오른쪽은 실패 후 재시도한 사례이고, 초록 곡선은 실패 때 내려갔다가 회복할 때 다시 올라가는 변화를 더 잘 반영합니다.

항상 높은 점수를 주는 것보다 현재 진행과 실패를 구별해 평가하는 것이 중요하다는 예시입니다. 이 두 사례는 저자의 정성적 근거이고, 그래프 자체가 정책 성공률이나 critic의 전반적인 정확도를 측정한 것은 아닙니다. 이제 학습한 정책을 실제로 빠르게 실행하는 방법으로 넘어가겠습니다.

## 24 · P020 · CUDA Graph

실제 로봇은 관측하고 계산하고 움직이는 동안에도 주변 상황이 변합니다. 계산이 오래 걸릴수록 관측 당시의 상황과 실행 시점의 상황이 달라질 수 있으므로 추론 지연을 줄이는 것이 중요합니다.

RoPE의 위치 관련 준비값과 attention mask 구조는 토큰 수, 위치 배치, 어느 정보를 읽을 수 있는지 같은 설정에 의존합니다. 그런데 배포 설정을 고정해 반복 추론한다면 같은 준비값을 매번 만들 필요가 없습니다. 저자들은 이 설정 의존 준비 계산을 forward 밖으로 옮겨 사전 계산하고 재사용합니다.

이렇게 실행 분할을 줄이고 한 forward 전체를 하나의 CUDA Graph로 캡처합니다. Figure 9의 위쪽은 여러 graph를 실행하며 호출 부담이 반복되고, 아래쪽은 한 graph로 실행해 그 부담을 줄이는 모습입니다. 관측에 따라 바뀌는 Q·K와 attention 결과는 계속 계산합니다. 재사용하는 것은 고정 설정의 준비값과 실행 구조입니다.

하나의 CUDA Graph 안에도 여러 GPU kernel이 들어갈 수 있습니다. 다음의 kernel fusion은 그 연산 경계 안쪽을 더 최적화하는 방법입니다.

## 25 · P038 · Kernel Fusion

Graph가 실행을 제출하는 부담을 줄였다면, kernel fusion은 연산 사이에서 중간값을 옮기는 부담을 줄입니다. GPU에서는 계산뿐 아니라 메모리에서 데이터를 읽고 쓰는 시간도 중요합니다. 이런 이동이 병목이면 memory-bound라고 부릅니다.

Figure 10의 왼쪽은 RMSNorm을 계산해 결과를 global memory에 저장하고, 다음 kernel이 읽어서 RoPE를 계산한 뒤 다시 저장하고, Attention이 다시 읽는 방식입니다. 오른쪽은 이 연산들을 하나의 fused kernel 안에서 이어 계산합니다. 중간값을 on-chip에서 재사용해 global memory 왕복을 줄입니다.

수학 문제를 풀 때 중간 답을 매번 적어 두고 다음 단계에서 다시 꺼내는 대신, 한 계산 흐름 안에서 계속 사용하는 것으로 생각할 수 있습니다. 다음 수식은 이 차이를 표현한 것입니다.

## 26 · P039 · Kernel Fusion의 계산

여기서 N은 RMSNorm, R은 RoPE입니다. 왼쪽은 q와 k를 정규화하고, 그 결과에 위치 회전을 적용하고, 마지막으로 Attention을 계산하는 단계식입니다. 별도 kernel로 실행하면 단계 경계마다 중간값을 저장하고 다시 읽는 비용이 생깁니다.

오른쪽은 같은 계산을 합성함수처럼 적었습니다. q와 k에 각각 N과 R을 적용한 값을 Attention이 사용합니다. 계산하려는 수학적 값은 같고, 실행 중간의 데이터를 어디에 보관하고 재사용하는지가 달라집니다.

식만 중첩해서 쓴다고 자동으로 fusion이 되는 것은 아닙니다. 보고서에서는 custom kernel로 그 실행 방식을 구현합니다. 여기까지가 최적화의 원리였고, 뒤의 ablation에서 실제 지연이 얼마나 줄었는지 확인하겠습니다. 먼저 모델의 조작 성능 실험을 보겠습니다.

## 27 · P040 · 시뮬레이션 벤치마크

Benchmark는 정해진 환경과 과제에서 여러 정책을 비교하는 평가 세트입니다. Figure 11은 각 평가가 다루는 로봇과 장면을 보여줍니다.

LIBERO는 단일 팔의 탁자 조작이고, LIBERO-Plus는 여러 조건 변화에 대한 대응을 봅니다. SIMPLER는 Google Robot과 WidowX의 실제 영상 조건을 맞춘 시뮬레이션 평가입니다. RoboCasa Kitchen은 이동형 단일 팔의 주방 조작, GR-1 Tabletop은 양팔 휴머노이드의 탁자 조작입니다. RoboCasa365에서는 단일 기술과 학습한·미지의 복합 절차를 평가합니다.

서로 다른 조작 능력을 확인하기 위해 여러 평가를 사용한 것입니다. 다음 결과는 각 benchmark의 학습 데이터로 fine-tuning한 뒤의 성능입니다. 하나의 정책을 모든 환경에 그대로 투입한 zero-shot 결과로 읽지는 않겠습니다.

## 40 · P062 · VQA 전후의 Attention

Figure 19의 위쪽은 원본 영상, 가운데는 Qwen3-VL 8B, 아래는 로봇 VQA 학습 후 RLDX-1-VLM입니다. 무지개색은 영상의 patch별 attention score를 덧씌운 heatmap입니다. 빨강·노랑 쪽은 상대적으로 높은 attention, 파랑 쪽은 낮은 attention으로 읽으면 됩니다.

## 41 · P063 · 합성 데이터 규모 실험

여기서 pool은 꺼내 쓸 수 있도록 준비된 합성 데이터 모음입니다. 설명을 위해 전체 합성 데이터가1만 개라고 가정하면,25% 조건은2,500개,50%는5,000개,100%는1만 개를 학습에 사용할 수 있는 조건입니다. 이 숫자는 개념 설명용입니다.

Pool 크기와 sampling 비율은 다릅니다. 이 실험은 실제 ActionNet 데이터를 고정하고 합성 데이터의 사용 가능한 규모를 바꿉니다. 합성을 사용하는 세 조건에서는 실제:합성을 뽑는 비율을 모두1:1로 유지합니다. 같은 비율로 실제·합성을 공부하더라도 합성 문제집이 더 두꺼워지는 것으로 생각할 수 있습니다.

따라서100%는 합성 데이터만 학습했다는 뜻이 아니라 전체 합성 pool을 사용했다는 뜻입니다. GR-1로 비교 범위를 제한하고 batch1024·60K steps로 pre-training한 뒤 같은 downstream 평가를 합니다. 이제 pool을 늘렸을 때 성능이 어떻게 바뀌었는지 보겠습니다.

> 조작: 왼쪽 frames 분포를 먼저 가리키고, 오른쪽 attempts 분포로 이동한다.

왼쪽에서 BC와 RECAP 단계들을 비교하면 완료 프레임 수가 줄어드는 것을 볼 수 있습니다. 오른쪽에서도 완료까지 비트는 횟수가 줄어듭니다. RECAP을 반복하면서 같은 목표를 더 적은 프레임과 시도로 마치는 방향으로 개선된 것입니다.

뒤쪽 round에서는 분포의 퍼짐도 작아집니다. 평균 성능만 개선된 것이 아니라 반복 실행의 일관성도 좋아졌다는 관찰입니다. 상자와 수염의 정확한 convention은 보고서에 충분히 정의되어 있지 않으므로, 표시 하나하나를 최댓값이나 최솟값으로 단정하지는 않겠습니다. 다음 장에서 본문이 명시한 숫자를 보겠습니다.

## 46 · P067 · RECAP 개선의 의미

BC는 완료까지1,056±326 frames와12.7±3.0번의 비틀기가 필요했습니다. RECAP3는353±22 frames와4.1±0.3번입니다. 두 지표 모두 약1/3 수준으로 줄었습니다.

여기서 ±는 표준편차입니다. 평균이 낮아진 데 더해 표준편차도 작아졌으므로, 반복 실행 결과가 더 일정해졌다고 읽을 수 있습니다. 이 작업의 완료 효율과 일관성이 함께 개선된 것입니다.

Round마다 rollout을 추가하고 critic과 policy를 갱신합니다. 따라서 추가 경험을 포함한 RECAP 반복 절차의 결과로 보겠습니다. 지금까지는 로봇이 작업을 얼마나 효율적으로 수행했는지였고, 다음은 모델이 행동을 계산하는 데 걸리는 시간입니다.

## 47 · P027 · 추론 지연 측정

Table 4는 같은 장비와 입력 설정에서 실행 방식을 바꾸며 policy 추론 지연을 측정합니다. RTX5090과 Core Ultra7 265K를 사용하고, ALLEX의 두 카메라 시점, 네 프레임, 행동 horizon40, Euler denoising4회 설정입니다.

먼저100회 warmup forward를 실행하고300회의 지연을 측정해 중앙값인 p50을 보고합니다. 초기 준비 영향을 줄이고 반복 실행 상태에서 비교하기 위한 설정입니다. p50은 측정 시간을 정렬했을 때 가운데에 해당하는 시간으로 이해하면 됩니다.

측정 대상은 policy가 행동을 계산하는 시간입니다. 카메라 관측부터 모터 실행까지의 전체 제어 지연은 아닙니다. Physics·memory를 제외한 모델과 모든 모달리티를 포함한 모델을 각각 비교합니다.

## 48 · P068 · 추론 최적화의 단계별 효과

오른쪽 All-modality 열을 따라가겠습니다. PyTorch Eager는71.2ms이고, CUDA Graph와 Torch Compile을 쓰면59.6ms입니다. 하지만 이 상태에서는 여러 subgraph로 나뉜 부분과 일부 연산 경계가 남습니다.

Static graph conversion을 더해 한 forward 전체를 하나의 CUDA Graph로 캡처하면48.9ms가 됩니다. 그 위에 kernel 최적화를 더해 중간 메모리 왕복을 줄이면43.7ms까지 내려갑니다. 앞에서 설명한 호출 부담과 메모리 이동의 감소가 실제 지연 감소로 이어진 것입니다.

왼쪽 physics·memory 제외 모델도67.0ms에서41.6ms로 비슷한 누적 개선을 보입니다. 표의 배수는 모두 첫 Eager 대비 누적값입니다. 다음 장에서 전체 개선과 마지막 단계의 추가 개선을 구분하겠습니다.

## 49 · P069 · 추론 최적화의 해석

전체 최적화의 speedup은 처음71.2ms를 마지막43.7ms로 나눈 약1.63배입니다. 지연시간으로 표현하면 약38.6% 감소입니다.

마지막 kernel 단계만의 추가 효과는 직전48.9ms와43.7ms를 비교한 약1.12배입니다. Kernel 하나만으로 전체1.63배가 된 것은 아닙니다. 표의1.19배·1.46배·1.63배를 서로 곱하지도 않습니다.

최종 두 모델 사이의 지연 차이는43.7−41.6,2.1ms입니다. 이 조건에서 physics와 memory를 함께 포함한 모델과 제외한 모델 사이에 관측된 차이입니다. 각 모듈의 독립 비용이나 다른 하드웨어에서도 같은 지연이라는 뜻으로 확대하지 않겠습니다. Graph와 kernel 두 수준의 최적화가 모두 효과가 있었다는 결과입니다.

## 50 · P029 · Conclusion

RLDX-1은 범용 시각·언어 이해에 움직임 인식, 장기 기억, 물리 센싱을 명시적으로 연결한 조작 모델입니다. VLM에서 행동 관련 특징을 만들고, MSAT에서 서로 다른 입력을 결합해 행동을 생성합니다.

여기에 합성 데이터 파이프라인, 세 단계 학습, 추론 최적화를 함께 설계합니다. 실험에서는 시뮬레이션과 실제 로봇의 조작 성능, VLM 표현의 선택, 합성 데이터의 규모 효과, RL 수행 개선과 추론 지연 감소를 확인했습니다.

이 결과들은 각 실험의 적응 과정과 지표에 따른 결과입니다. 범용 모델을 만들었다는 기여와, 모든 작업을 추가 학습 없이 해결한다는 주장은 구분해야 합니다. 마지막으로 이 연구를 읽고 든 의견과 남은 질문을 말씀드리겠습니다.

## 51 · P028 · 나의 의견

제가 이 연구에서 인상적으로 본 점은 조작에 필요한 정보를 기능별로 구조에 연결한 것입니다. 현재 영상만으로 알기 어려운 움직임, 과거 사건, 접촉 정보를 별도 모듈과 stream으로 다룹니다. 범용 이해를 실제 조작에 필요한 입력과 표현으로 연결하려는 접근으로 읽었습니다.

중간층과 로봇 VQA 비교는 행동 모델에 어떤 특징을 전달하는지가 중요하다는 근거입니다. 합성 데이터와 RECAP의 개선도 확인할 수 있었지만, 생성·필터 단계나 추가 데이터·RL 각각의 기여를 더 나눠 비교한 결과도 보고 싶습니다.

또 성공률, 완료 프레임 수, policy 추론 지연은 서로 다른 지표입니다. 성능이 좋아졌다는 말을 할 때 무엇이 개선됐는지를 구분해야 합니다. 같은 데이터와 학습 예산에서 구성 요소를 하나씩 비교하면 각 설계의 기여가 더 분명해질 것 같습니다.

## 52 · P030 · 한계와 미해결 질문

마지막은 원문을 읽으면서 남겨 둔 질문입니다. Memory는 저장 간격을 H+1이라고 설명하지만 queue 식에는 H 간격이 나타납니다. 매 시점의 queue 갱신과 초기화 규칙도 더 확인할 필요가 있습니다.

MSAT 앞부분은 noisy actions가 A stream에 들어간다고 명시하지만, Physical Sensing 마지막 요약에는 C stream이라는 서술이 나옵니다. 앞의 구조 설명을 기준으로 읽되 표기의 불일치는 남겨 두었습니다. Task augmentation도 가능한 작업을 만들려는 전략은 설명하지만, 구체적인 skill 목록과 실행 가능성 판정 규칙은 더 확인해야 합니다.

Figure 7의 Franka 비중은 표시값 합이101.0이고 본문은8:2로 설명해 실제 혼합 설정을 확인할 질문이 남습니다. 이러한 문서의 불확실성을 곧바로 모델이 작동하지 않는 증거로 보지는 않겠습니다.

후속 검증에서는 모듈·필터·RL의 독립 비교, 동일한 데이터·계산 예산, 반복 평가의 불확실성과 전체 제어 지연을 더 보고 싶습니다. 보고된 결과와 설계 의도, 아직 확인하지 못한 부분을 구분하는 것으로 발표를 마치겠습니다. 감사합니다.
