SLIDE 8
Core Idea
FCN

08
U-Net은 해당 아이디어를 2014년에 구현한
“Fully Convolutional Networks for Semantic Segmentation”의 FCN을 참조했다.
FCN의 모든 것을 설명하기에는 너무 과하기 때문에 FCN 논문에서 나온 효과적인 방법론들과 노벨티만을 보겠다.
U-Net은 FCN의 2가지 핵심 방법론을 사용했다.

Upsampling Convolution

앞서 말했듯이 일반 Conv의 feature map의 spatial resolution이 너무 작아지기 때문에, 원본 이미지의 각 픽셀에 대응하는 prediction을 바로 만들 수 없다.
작아진 feature map을 segmentation을 위해 키우기 위해 Upsampling Convolution을 이용한다.

Skip Connection

Upsampling이 downsampling하면서 잃어버린 정보를 되살릴 순 없기 때문에,
Upsampling시 필요한 얕은 층의 CNN 정보들(경계 등등)을 같이 볼 수 있도록 도와준다.

SLIDE 14
Architecture
왜 concat할까?

14
기존 FCN skip은 element-wise addition을 했다.
하지만, U-Net은 channel 방향으로 그저 concat한다.
그 이유는
Encoder: [경계 정보, 위치 정보, texture 정보]
Decoder: [고양이일 가능성, 객체 의미 정보, 큰 구조 정보]
라고 가정하면,

addition 시
                           [경계 + 고양이일 가능성, 위치 + 객체 의미, texture + 큰 구조]
처럼 channel끼리 강제로 대응해서 데이터를 섞는 느낌이다.
대신 channel수가 안 늘어나 계산 속도가 빠르다.

concat 시
                             [ 경계, 위치, texture, 고양이 일 가능성, 객체 의미, 큰 구조 ]
처럼 말그대로 정보를 그대로 보존한 채 말그대로 동시에 볼 수 있다.
대신 channel 수가 늘어나 계산이 복잡하다.

SLIDE 16
Training
학습: 큰 tile, batch size 1, momentum 0.99

16
왜 큰 tile인가?
valid conv 때문에 input보다 output이 작다.
작은 tile을 여러 개(batch size가 1이 아닌 다수이면)하면 경계 손실의 비중이 커진다.

SGD · batch size 1
GPU 메모리를 여러 샘플 대신 큰 입력 tile에 쓴다.
Momentum 0.99
이전 학습 샘플의 영향이 업데이트에 계속 반영된다.

얕은 Conv1D (kernel=3 예시)
t2–t4: 손 열기 → 잡기 → 들기
깊은 feature (넓은 수용영역)
t0–t5: 접근 → 잡기 → 이동

시간 해상도
T=16   →   8   →   4   →   8   →   16
Skip concat: 높은 시간 해상도의 encoder feature를 decoder에 채널 방향으로 붙인다
긴 흐름과 t3의 gripper 변화를 결합해 timestep별 출력을 만든다
동작·T=16은 예시. local + context는 구조적 해석이며 skip만의 효과를 분리한 실험은 아니다.
