### 한 문장

Table 7은 실제로 어떤 연산들을 한 kernel 안에서 이어 계산하도록 만들었는지 보여준다.

### 본문

| 대상 | 원래 연산의 흐름 | Fusion으로 함께 처리하는 것 |
| --- | --- | --- |
| Vision·Memory attention | RoPE → Attention | 위치 회전 + Attention |
| LLM attention | RMSNorm → RoPE → Attention | 정규화 + 위치 회전 + Attention |
| Residual·Norm | 두세 특징의 덧셈 → LayerNorm/RMSNorm | 덧셈 + 정규화 |
| SwiGLU | 각 stream의 특징 변환 | Grouped / fused SwiGLU |

<p class="callout"><span class="label interpretation">직관</span> 앞 장의 합성함수 비교가 실제로 적용된 위치다. 중간 결과를 global memory로 내보냈다가 읽는 경계를 줄인다.</p>

각 kernel 이름보다 <strong>어느 경계의 저장·재읽기를 줄였는지</strong>를 이해하면 된다.

### 요점

Fusion은 Attention 하나에만 쓰지 않는다. Residual·normalization·FFN 주변의 반복 비용도 줄인다.

### 발표 메모

Table7의 8개 이름은 fused_vision_attention, fused_llm_attention, fused_add2_layernorm, fused_add2_rmsnorm, fused_add3_rmsnorm, fused_memory_attention, grouped_swiglu, fused_mlp_swiglu다. add3의 세 번째 입력은 DeepStack feature h_ds다. Table7은 연산 목록이며 kernel별 latency를 따로 분해한 표는 아니다.
