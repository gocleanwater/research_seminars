# 논문 공부 → HTML 세미나 제작 규칙

갱신: 2026-11-17 (2026-11-09 정리 시작). 근거는 실제 대화와 RLDX-1의 `review/FEEDBACK.md`다. 이 문서는 재발 방지용 규칙이며 발표 화면에 넣는 내용이 아니다. 근거와 논문별 예외는 `FEEDBACK_LESSONS.md`를 함께 읽는다.

## 시작할 때

- **H01 최신 지시:** 현재 요청, 프로젝트 상태, 피드백 이력을 먼저 확인한다. 예전 페이지 제한·제작 방식·편집 원본을 그대로 재사용하지 않는다. 기존 승인과 새 수정 허가는 구분한다.
- **H02 작업 범위:** 구조 준비, 공부, 목차, 전체 제작, 특정 장 수정, 대본 작성 중 지금 요청한 범위만 진행한다. Obsidian 설치·Notion 이관·다른 도구 전환을 임의로 끼워 넣지 않는다.
- **H03 자료 연결:** Section 공부 MD, 질문노트, 원문과 출처를 읽고 무엇을 공부했는지 확인한다. 채팅에만 있던 내용을 안다고 가정하지 않는다. 근거가 없으면 미확인으로 남긴다.

## 설명을 구성할 때

- **H04 전체 흐름:** 기본은 전체 목차와 맥락의 초안을 만든 뒤 장별로 수정한다. 사용자가 장별 선승인을 요구하면 그 모드로 바꾼다. 고정 장수·시간·청중을 요구해 작업을 막지 않는다.
- **H05 상세함과 밀도:** 공부한 세부 내용은 보존하되 모든 질문·상세 단위를 한 장씩 만들지 않는다. 관련 내용은 묶고, 화면에는 핵심과 그림, 상세 풀이·설정은 해설/대본에 둔다. 필요하면 장을 늘리되 글자를 작게 줄여 억지로 넣지 않는다.
- **H06 선수 설명:** 문제와 필요성 → 입력·출력·개념 → 구조와 정보 흐름 → 수식 → 학습·평가 순서를 기본 점검한다. 구조 설명을 학습 설정 뒤에 남기지 않는다. 중간 변환(예: 행동→simulator→rollout 영상)을 생략하지 않는다.
- **H07 원문과 이해:** 사실·저자 주장/원인 해석·우리의 직관·설명용 예시·미해결을 구분한다. 이 구분을 위해 불필요한 분류 배지를 화면에 추가할 필요는 없다. 쉬운 말과 출처로 전달한다.
- **H08 필요성과 차이:** 모듈/학습 단계의 이름만 나열하지 말고 왜 필요한지, 기존 방식과 무엇이 다른지, 실제로 무엇을 바꾸는지 설명한다. 데이터의 수집 목적과 학습 단계의 역할도 먼저 설명한다.

## 그림과 수식을 만들 때

- **H09 원문 그림:** 원문 그림과 그래프를 우선 활용하고 출처·가공 여부를 남긴다. 참고 발표는 구조와 직관적 설명을 참고하는 것이며 그대로 복제하거나 디자인 승인으로 간주하지 않는다.
- **H10 연결이 보이는 그림:** 전체 구조 → 모듈 확대 → 입력/중간 처리/출력의 단계별 연결 → 전체 복귀가 가능한지 확인한다. 화살표 시작·끝, 토큰 묶음, 범례와 필요한 하단 연결부가 실제로 보이는지 검사한다. 확대 화면에 인접 모듈의 잘린 제목을 남기지 않는다.
- **H11 원문 기호 보존:** 원문 기호를 주석·마스크·이름표로 덮지 않는다. 원문의 시각 표기와 검증한 연산 의미가 다르면 그림 밖 설명에서 구분한다. 참조 손그림은 표시 방식의 참고이지 논문 사실의 근거가 아니다.
- **H12 수식의 의미:** 정책/방법의 정체와 지금 식의 역할(입력 구성·학습 목표·추론 갱신 등)을 먼저 설명한 뒤 항과 연산을 풀어 쓴다. `$...$`/`$$...$$` LaTeX와 수식 렌더러를 사용한다. 발표 대본에서도 아래첨자·위첨자·그리스 문자·연산을 수식으로 표기하며, `c t`, `v star`, `u theta`, `1 minus tau`처럼 발음을 풀어 쓰지 않는다. 기호·조건 입력·차원/시간 축·학습 target·함수와 출력값을 정의한다. 식만 보여주거나 숫자 예시만으로 수식 설명을 대체하지 않는다. 예시를 원치 않으면 해당 식의 항과 의미를 설명한다.
- **H13 혼동 방지:** clean target와 noisy 후보, 실제 로봇 시간과 denoising 시간, 예측 velocity와 최종 행동을 구분한다. 구체적인 숫자·층·학습 설정이 화면의 이해를 방해하면 삭제 대신 상세 해설로 옮긴다. 다른 논문에서는 해당 논문의 정의를 다시 확인한다.

## 실험을 설명할 때

- **H14 결과 전 맥락:** 벤치마크/로봇/과제의 의미와 사진·성공 기준을 먼저 소개한다. 약어·과제명·평균의 구성만 던지고 결과표로 넘어가지 않는다.
- **H15 지표와 조건:** 데이터 pool 크기와 sampling 비율, 성공률과 progress score, value와 확률, latency p50과 전체 제어 지연, 누적 배수와 직전 단계 배수를 구별한다. 미보고는 0으로 바꾸지 않는다. 원문 표를 재구성하면 모든 값과 단위를 대조한다.
- **H16 관측과 인과:** 설정 → 관측 결과 → 저자 해석 → 우리가 이해한 직관 → 실험이 확인하지 못한 범위를 연결한다. 통합 시스템의 개선을 특정 모듈의 독립 효과로 단정하지 않는다. attention 시각화·몇 가지 사례·단일 작업 결과를 일반 증명으로 확대하지 않는다.
- **H17 부록과 제외 범위:** 사용자가 제외한 실험을 한계/의견/대본에 다시 넣지 않는다. 발표에서 제외한 것과 공부 기록을 삭제하는 것은 다르다. 관련 본문에 합칠 때 중복을 줄이고 상세 원본과 연결을 보존한다. 부록은 모든 논문에서 무조건 빼는 것이 아니다.

## 화면·조작·보존

- **H18 화면과 글꼴:** 짧은 제목·의미 단위 줄바꿈·충분한 여백을 사용한다. 제목은 핵심 개념을 나타내는 짧은 명사구를 기본으로 하고, 긴 설명 문장은 본문·대본에 둔다. 현재 선호는 Arial 계열과 읽기 쉬운 한글 고딕, 자간 0이며 프로젝트 설정을 먼저 확인한다. CSS 지정만으로 실제 글리프 사용을 확인했다고 하지 않는다. 글꼴·수식 변경 후 넘침·정렬을 실제 화면에서 다시 검사한다.
- **H19 PPT 같은 탐색:** 다음/이전 키는 단계와 장 사이에 일관되게 동작해야 한다. 뒤로 넘어가면 이전 장의 마지막 단계에서 역순 탐색하고, 페이지 번호로 직접 이동하면 첫 단계에서 시작한다. 입력·텍스트 선택·버튼·그림 확대·OS 단축키를 가로채지 않는다. Esc는 맨 위 팝업부터 닫는다.
- **H20 모바일:** 하단 도구막대가 좁은 화면에서 넘치지 않아야 한다. 실제 메뉴 높이·safe area·터치 영역·화면 회전·페이지 입력을 확인한다. 데스크톱 검사로 실제 휴대폰 검증을 대신했다고 하지 않는다.
- **H21 편집 원본:** 해당 프로젝트의 현재 canonical source를 먼저 찾는다. 생성 HTML만 수정하지 않는다. 이전 JSON/백업/일회성 마이그레이터를 현재 원본으로 오인하지 않는다. Section 공부 기록과 발표용 원본은 역할을 구분하고 연결한다.
- **H22 변경과 재개:** 장 ID와 화면 번호를 분리한다. 사용자 번호 지시를 현재 버전·제목·ID에 대응시켜 확인한다. 모호해서 다른 장을 바꿀 위험이 있으면 질문한다. 통합/퇴역 ID를 다른 의미로 재사용하지 않는다. 대본·원본·해설·링크 매핑을 함께 갱신하고 이전 버전을 보존한다.
- **H23 실제 검증:** 실제 HTML에서 PNG를 만들고 직접 확인한다. 생성형 그림으로 결과 화면을 대신하지 않는다. 변경 범위에 맞춰 수식·출처·표 값·겹침·그림·키보드·직접 링크·필요한 base 경로를 검사한다. 코드/설정만 읽고 화면을 검증했다고 하지 않는다. 무관한 광범위 검사는 반복하지 않는다.
- **H24 승인·공개·기록:** 제작 허가, 수정 요청, 결과물 승인, push, 실제 배포 완료를 구분한다. 논문별 공개 권한을 다른 논문이나 새 작업으로 복사하지 않는다. 실제 피드백·반영 위치·검증·보류 이유·승인 여부를 파일에 기록하고 완료되지 않은 것을 완료로 쓰지 않는다.

- **H25 의미 중복 검토:** 보완 요청을 처리할 때 기존 주제와 설명 순서를 먼저 한 문장으로 확인하고, 추가할 설명이 들어갈 위치를 정한다. 사용자가 순서 변경을 요청하지 않았다면 보충 이유·예시를 도입이나 중심 주제로 올리지 않는다. 수정 전에 대상과 인접 단계의 화면·대본을 함께 읽고 각 단계의 질문·새 정보를 비교한다. 같은 결론을 전체 그림과 예시로 나누어 반복하지 않는다. 같은 핵심의 예시는 한 그림에서 짧게 설명한다. 완료 전 해당 구간을 이어 읽어 개념 중복과 전환을 확인하고, 이를 화면 넘침·탐색 자동 검사와 구별해 기록한다.

## 작업 완료 전 짧은 확인

해당 작업에 적용되는 항목만 확인하고 `review/PROGRESS.md` 또는 실제 검증 기록에 남긴다.

```markdown
- 적용한 규칙: H__ / H__
- 확인한 Section 공부 기록과 원문:
- 수정한 canonical source와 영향받는 슬라이드 ID:
- 유지할 기존 주제·설명 순서 / 요청된 보충을 넣은 위치:
- 각 단계가 답하는 질문·새 정보 / 인접 화면·대본의 의미 중복 검토:
- 삭제·통합한 반복 / 수정하지 않은 범위:
- 화면/대본/상세 기록의 배치와 누락·중복 확인:
- 실제 실행한 검사와 결과:
- 실제 사용자 승인 / 아직 검토 전:
- 이번에 남은 질문과 다음 작업:
```

이 문서는 품질 판단을 대신하는 자동 채점기가 아니다. 완료 체크를 붙일 때마다 실제 근거가 있어야 한다.
