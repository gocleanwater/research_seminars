# 공통 논문 세미나 하네스와 설명 UI 잔여물 정리

사용자 요청: 설명 전용 코드/산출물까지 재정리하고, 다른 논문도 공부 이후 같은 품질의 HTML 발표를 만들 수 있는 환경 구축.

1. RLDX의 숨은 설명 팝업·이벤트·CSS·발표HTML 내 설명 데이터 제거. 공부MD/대본/피드백/원본 단위와 버전 이력 보존. 설명 UI를 호출하던 검증은 canonical source와 manifest 보존 검증으로 변경.
2. 공통 템플릿을 실행 가능한 대본 중심 환경으로 확장. Section MD 하나에서 화면·단계·대본·출처를 관리하고, 오프라인 HTML/Part 분리본·대본 생성. 설명 메뉴는 만들지 않음. 논문별 내용·장수·권한을 복사하지 않음.
3. 프로젝트 생성·Section 기록·검증·피드백·정리 명령과 다른 채팅에서 재개할 안내 제공. 피드백/공부 파일은 정리 명령의 대상 밖으로 고정.
4. 임시 새 논문 프로젝트에서 생성→빌드→브라우저 검증→피드백 저장→정리 루프를 직접 실행. 기존 RLDX도 렌더/키보드/Part/단위 보존 확인. 외부 저장소/Pages는 새로 만들거나 배포하지 않음.

선택: 현재 종속적인 RLDX 구조 전체를 복제하지 않고, 공통 Markdown 렌더링·발표 탐색만 재사용한다. 품질 평가는 자동 형식 검사와 사람이 하는 의미·흐름 검토를 구분한다.
