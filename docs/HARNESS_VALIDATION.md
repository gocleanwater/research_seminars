# 재사용 세미나 환경 — 2026-11-18

## 준비한 환경

- `scripts/new_seminar.py`: 기존 폴더를 덮어쓰지 않고 논문별 작업 폴더를 생성한다. 이전 논문의 내용·장수·권한을 복사하지 않는다.
- `seminar-template/sections/*.md`: 화면·단계·대본·출처의 한 편집 원본. Section 공부는 별도 MD로 보존한다.
- `scripts/seminar.py`: study / build / check / feedback / clean / serve / package.
- 생성 결과: 그림·수학 글꼴을 내장한 오프라인 index/presentation/Part HTML과 별도 대본. 설명 팝업·숨은 설명 데이터는 넣지 않는다.
- 직접 수정한 대본은 build가 덮어쓰지 않고 Section 원본에 반영하도록 중단한다. 원본 화면/그림/설정이 바뀐 뒤 재빌드하지 않으면 check가 알아낸다.
- correction과 praise를 모두 원문으로 기록한다. 자동 형식·브라우저 검사 뒤 원문·의미·중복·자연스러운 연결을 사람이 검토한다.
- clean은 기본적으로 후보만 보여주며, 적용해도 공부·대본·피드백·최신/참조 캡처·Git 추적 파일·현재HTML을 보존한다.

- 의존성은 필요한 Markdown/수학/브라우저 패키지11개만 고정했다. 로컬 캐시만 쓰는 설치에서 정책 확인용 메타데이터가 없어 중단됐고, 온라인 정책 확인을 거친 고정 lockfile 설치는 통과했다. 브라우저 다운로드/패키지 설치 스크립트는 실행하지 않았다. 설치 환경은 약21MB이며 실제 검증은 설치된 Chrome을 사용했다.
- `scripts/test_seminar_harness.py`:8개 검사 통과. 새 폴더/중복 거부, 단계 파싱·누락·중복ID, 입력 경로 제한, 칭찬/수정의 append-only 저장, 공부 기록 덮어쓰기 방지, 최신/피드백 참조/추적 캡처·캐시 보존.
- `scripts/smoke_seminar_harness.py`:임시 새 논문 폴더 생성→그림 내장→build/check→수정 대본 보호→미빌드 화면 감지→Section 기록→긍정 피드백 저장→정리 보호→공개 후보HTML 포장→실제 브라우저 검사 통과. 임시 작업 폴더는 검사 뒤 제거했다.

- 새 틀 로컬 서버의 HTTP200 응답 확인 후 검사 서버 종료. 기존 RLDX 서버는 변경하지 않았다.

## 기존 RLDX 코드 정리

숨은 설명 팝업·핸들러·스타일·내장 설명 데이터·전용 HTML 렌더러를 제거했다. 오래된 crop/비교 CSS도 현재 소스/실행 코드에서 참조되지 않음을 확인한 뒤 삭제했다. 설명 팝업을 열던 검증은 Section MD와 manifest의 원본 단위 보존 검증으로 바꿨다.

- 실제 발표 내용/대본/원문121단위는 유지. 사용하지 않는 렌더러 제거 전후의 생성 슬라이드 마크업 SHA-256 동일 확인.
- HTML4개 합계 약7.67MiB 감소. 파일당 전체HTML은20.63→18.40MiB, Part1은20.26→18.36MiB, Part2는19.67→18.36MiB.
- 전체45장 렌더, 넘침/JS오류/외부요청0.35개 구조 단계·6개요약 단계·5개문제 단계·전체탐색·Part1 21/Part2 24·모바일10레이아웃·수학/글꼴·원본/대본 보존 검사 통과.
- 원문/공부/피드백/버전 이력은 삭제하지 않음. 과거 버전 파일에는 당시 코드가 남을 수 있지만 현재 빌드 경로에서는 사용하지 않는다.

실제 GitHub 저장소 생성·Pages 배포는 수행하지 않았다. `deployment/`의 워크플로는 비활성 예시이며 새 논문 공개 권한은 별도로 확인한다.
