- 이번 채팅의 직접 요청과 공통 연구 폴더 기준 `rldx-1-seminar/review/FEEDBACK.md`에 남은 2026-11-05~18 사용자 피드백 기록을 검토했다.
- 과거 채팅 전체를 새로 읽었거나 과거의 모든 검증을 재실행했다는 의미는 아니다. 원본 피드백 기록과 발표 소스는 보존한다.
- 실제 결함, 설명 보완, 취향, 작업 방식 변경을 모두 '실수'로 단정하지 않는다. 재사용 가능한 판단 원칙과 특정 논문에만 적용할 결정을 구분한다.
- 아래 규칙 ID는 `SEMINAR_PLAYBOOK.md`의 H01–H25에 대응한다.

## 수정 전·완료 전 필수 점검 — 반복된 중복 피드백 반영

이번 반복의 원인: 화면의 그림·배치가 다르면 새로운 설명이라고 취급했다. 전체 정보 교환 그림과 행동 토큰 하나의 예시는 같은 결론을 반복했고, 새 화면 하나만 확인한 채 앞뒤 화면과 대본의 의미 중복을 놓쳤다. 브라우저·수식·넘침 검사가 통과해도 이 문제는 검증되지 않는다.

1. **수정 전:** 기존 설명의 중심과 순서를 짧게 정리하고, 사용자가 요청한 변경과 보존할 부분을 구별한다. 최신 결과물의 번호·고정 ID·제목을 확인하고, 해당 단계와 앞뒤 단계의 화면·대본을 함께 읽는다. 과거 번호로 다른 단계를 수정하지 않는다.
2. **추가 전:** 각 단계가 답하는 질문과 새로 전달하는 내용을 각각 한 문장으로 적어 비교한다. 문장·그림이 달라도 같은 질문과 결론이면 한 단계로 묶는다. 같은 원리를 보여 주는 예시는 해당 그림을 유지한 채 짧게 말한다.
3. **설명 순서:** 왜 필요한가→그림에서 무엇이 들어오고 어떻게 달라지는가→핵심 원리 순으로 설명한다. RMSNorm·QKV·FFN 등의 세부 이름을 먼저 나열해 이해를 대신하지 않는다. 필요한 구현 세부는 공부 기록·해설에 보존한다.
4. **화면·대본 동시 편집:** 화면의 색·자리·화살표를 말하는 순서와 맞춘다. 합치거나 제외한 설명이 다른 대본·요약에 독립 단계로 다시 남지 않게 확인한다. 이해에 필요한 한 문장과 반복 강의를 구분한다.
5. **완료 전:** 수정 전후의 도입과 흐름을 비교해 보충 내용이 본래 주제를 밀어내지 않았는지 확인한다. 변경 구간을 이전 단계부터 다음 단계까지 실제 화면과 대본으로 이어 읽는다. 새로 추가된 내용, 삭제/통합한 중복, 수정하지 않은 범위를 기록한다. 같은 개념을 전체도식→예시라는 이유로 연속 두 번 설명하지 않는다.
6. **검증 보고:** 의미·설명 순서를 검토한 결과와 렌더링·탐색 검사 결과를 분리해 적는다. 자동 검사만으로 '중복 없음'이나 사용자 만족을 선언하지 않는다. 부족한 부분을 사용자에게 다시 찾아 달라고 넘기지 않는다.

이 점검은 모든 장에 새로운 서류를 만드는 절차가 아니다. 변경한 구간에만 짧게 적용하고, 실제 검토 근거를 `review/PROGRESS.md`에 남긴다. 사용자가 다른 구성을 직접 요청하면 그 지시를 우선한다.
